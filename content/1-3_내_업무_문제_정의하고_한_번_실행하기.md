## 1. 문제 정의 질문 4개와 문장

Claude에게 업무를 맡기기 전에 아래 질문 네 개에 먼저 답합니다.

### 질문 4개

| 질문 | 적을 것 | 예: 월말 입퇴사 현황 |
|---|---|---|
| 1. 어떤 일인가 | 언제, 얼마나 자주 | 매월 말일, 월 1회 |
| 2. 무엇을 받아서 무엇을 만드나 | 입력 파일과 결과물의 모양 | 인사시스템에서 내려받은 직원 명부 CSV → 소속별 현황 표와 입퇴사자 명단 |
| 3. 어디서 시간이 가장 많이 드나 | 병목과 1회 전체 소요 시간 | 입사일과 퇴사일을 하나씩 걸러 세고 전월 숫자와 맞추는 일, 반나절 |
| 4. 잘 됐는지 무엇으로 아나 | 숫자나 대조로 판정할 수 있는 기준 | 전월 말 재직 + 이번 달 입사 − 이번 달 퇴사 = 이번 달 말 재직 |

가장 자주 비는 칸은 4번입니다. "깔끔하면", "정확하면"은 기준이 아닙니다. **누가 봐도 맞다, 틀리다가 갈리는 문장**이어야 검수에 쓸 수 있습니다.

### 문제 정의 문장

네 답을 아래 틀에 넣어 한 문장으로 묶습니다.

```text
나는 [언제]마다 [입력]으로 [출력]을 만드는데, [병목] 때문에 [시간]이 걸린다. [확인 기준]이 맞으면 잘 된 것이다.
```

월말 입퇴사 현황이라면 이렇게 됩니다.

> 나는 매월 말일마다 인사시스템에서 내려받은 직원 명부로 소속별 입퇴사 현황 보고서를 만드는데, 입사일과 퇴사일을 하나씩 걸러 세는 일 때문에 반나절이 걸린다. 지난달 재직 인원에 입사자를 더하고 퇴사자를 뺀 값이 이번 달 재직 인원과 같으면 잘 된 것이다.

### 검수 3칸

결과물이 나오면 확인 기준으로 대조해 세 칸에 나눠 적습니다.

| 칸 | 적을 것 | 예 |
|---|---|---|
| 맞은 것 | 확인 기준으로 대조해 맞은 것 | 소속별 인원의 합이 전체 인원과 같다 |
| 틀린 것 | 숫자, 기준, 사실이 틀린 것 | 부서 이름을 원자료와 다르게 줄여 썼다 |
| 빠진 것 | 요청했거나 필요했는데 없는 것 | 무엇을 기준으로 셌는지 설명이 없다 |

**결과를 어디까지 믿을지는 이 표가 정합니다.** 맞은 것은 확인 기준으로 대조한 만큼만 믿습니다.

확인한 범위에서 틀린 것이 없으면 "없음"으로 적습니다. 그때도 어떤 기준으로 셌는지와 빠진 맥락은 확인합니다.

## 2. 한결커머스 월말 입퇴사 현황 만들기

시간이 부족하면 강사 화면을 보며 결과만 확인하고, 수업 뒤에 이어서 해 보세요.

### 실습 1. 9월 입퇴사 현황 만들기

**사용할 파일**: [employees.csv](/practice-files/employees.csv)

2026-09-30 기준으로 인사시스템에서 내려받은 한결커머스의 직원 명부이고, 재직자와 7~9월 퇴사자를 합쳐 322행입니다. 이 실습에 쓰는 열은 사번, 이름, 소속(본사, 물류센터), 부서, 입사일, 퇴사일, 재직상태입니다. 이 파일에는 함정이 하나 있습니다.

> ⚠️ **주의** 실습 파일은 모두 교육용 가상 데이터입니다. '한결커머스'와 직원, 지원자, 응답은 강의를 위해 만든 것이며 실제 회사나 사람과 관계가 없습니다. 내 회사 데이터로 옮길 때는 [데이터 보안 기준](/guide/9-2/#2-실데이터를-쓰기-전에-확인할-것)부터 확인하세요.

이 데이터가 진짜라면 이름, 사번, 이메일이 붙은 인사 데이터라서 3단계(개인정보)입니다. 지금은 가상 데이터이므로 개인 계정에서도 그대로 올려 실습합니다.

확인 기준에 쓸 8월 말 재직 인원은 지난달 보고서에 있습니다.

| 지난달 보고서 | 본사 | 물류센터 | 합계 |
|---|---|---|---|
| 8월 말 재직 | 121 | 184 | 305 |

**먼저 실행합니다.** 파일을 내려받아 새 대화에 올리고, 아래를 붙여 넣으세요.

```text
[맥락]
나는 한결커머스 인사팀 담당자야. 첨부한 employees.csv는 2026-09-30 기준으로 인사시스템에서 내려받은 직원 명부이고, 7~9월 퇴사자도 들어 있어.
이 현황은 매월 경영진 보고에 들어가.

[원하는 것]
2026년 9월 입퇴사 현황을 만들어 줘.
1. 9월 말 재직 인원 (본사, 물류센터, 합계)
2. 9월 입사자 수와 명단 (사번, 이름, 소속, 부서, 입사일)
3. 9월 퇴사자 수와 명단 (사번, 이름, 소속, 부서, 퇴사일)

[형식]
소속별 요약 표 1개와 명단 표 2개. 설명은 표 아래 3줄 이내로.

[완료 기준]
- 숫자는 파일을 직접 계산해서 써 줘.
- 재직과 퇴사를 어떤 열로 판단했는지 한 줄로 적어 줘.
- 확실하지 않은 값은 [확인 필요]라고 표시해 줘.
```

> 💡 **생각할 시간** 결과를 보기 전에, 무엇을 확인하면 맞는지 알 수 있을지 하나만 정해 두세요. 문제 정의 문장의 확인 기준과 위 표의 8월 말 숫자가 힌트입니다.

**결과가 나오면 검산합니다.** 소속별로 8월 말 재직에 9월 입사를 더하고 9월 퇴사를 뺀 값이 Claude가 쓴 9월 말 재직과 같아야 합니다.

이 실습은 월중 소속 이동이 없다고 가정합니다. 실무에서 소속별로 검산할 때는 전입과 전출도 반영하고, 전월 보고서와 같은 기준으로 셉니다.

**검산이 맞지 않으면** 이유를 추측하지 말고 증상을 그대로 말합니다.

```text
8월 말 재직 305명(본사 121, 물류센터 184)에 9월 입사를 더하고 9월 퇴사를 빼서 계산하면, 네가 쓴 9월 말 재직과 맞지 않아.
소속별로 어디서 몇 명 차이가 나는지 보여 주고, 차이를 만든 행을 찾아 줘.
```

**검산이 맞아도 한 번 더 묻습니다.** 같은 사실을 담은 두 열이 서로 다른 말을 해도, 정리된 결과에서는 티가 나지 않습니다. 따로 물어봐야 나옵니다.

```text
재직상태 열과 퇴사일 열이 서로 맞지 않는 행이 있는지 찾아 줘. 사번, 이름, 두 열의 값을 표로 보여 줘.
```

**그다음 검수 3칸을 채우고 규칙을 받아 둡니다.** 아래 표를 메모장에 옮겨 채우세요.

| 맞은 것 | 틀린 것 | 빠진 것 |
|---|---|---|
| | | |

확인한 기준은 다음 달에도 쓰도록 같은 대화에서 한 줄 규칙으로 받아 둡니다.

```text
방금 확인한 판단 기준을 다음 달에도 그대로 쓸 수 있게 한 줄 규칙으로 정리해 줘.
입사일이 기준일 뒤인 입사 예정자와, 퇴사일이 기준일 뒤인 재직자를 어떻게 처리하는지도 밝혀 줘.
```

**마지막으로 다음 달에도 맞는 규칙인지 봅니다.** 규칙을 받았으면 정답 예시 끝의 경계 샘플 3행으로 점검합니다.

## 3. 내 문제 정의하기

### 실습 2. 내 업무로 질문 4개에 답하고 한 문장으로 쓰기

사전 준비로 업무 후보를 가져왔다면 그중 하나를 고릅니다. 후보가 없으면 [HR 사례 카드](/guide/9-1/#카드-한눈에-보기)에서 하나 고릅니다. 처음 맡겨 볼 업무는 아래 조건에 맞을수록 좋습니다.

| 이런 업무가 좋습니다 | 이유 |
|---|---|
| 한 달에 한 번 이상 반복된다 | 숙제로 2~3번 더 돌려 볼 수 있다 |
| 입력 파일이나 문서가 있다 | Claude에게 줄 재료가 분명하다 |
| 확인 기준을 숫자나 대조로 쓸 수 있다 | 검수 3칸을 채울 수 있다 |
| 결과를 사람이 본 뒤에 내보낸다 | 틀려도 바로 사고로 이어지지 않는다 |

질문 4개는 혼자 답해도 되지만, Claude에게 하나씩 물어보게 하면 빠뜨린 칸이 드러납니다. 새 대화에 아래를 붙여 넣되, 첫 줄의 [회사 규모와 업종]과 [직무]만 내 것으로 바꿉니다. 아래쪽 문장 틀의 [ ]는 Claude가 채울 칸이니 그대로 둡니다.

```text
나는 [회사 규모와 업종]의 HR 담당자이고 [직무]를 맡고 있어.
AI에게 맡겨 볼 업무 하나를 정하려고 해. 아직 결과물은 만들지 마.

아래 질문 4개를 한 번에 하나씩 물어봐 줘. 내 답이 모호하면 한 번 더 물어봐 줘.
1. 어떤 일인가 (언제, 얼마나 자주)
2. 무엇을 받아서 무엇을 만드나
3. 어디서 시간이 가장 많이 드나 (가장 오래 걸리는 단계와 1회 전체 소요 시간)
4. 잘 됐는지 무엇으로 아나

다 답하면 아래 틀에 맞춰 문제 정의 문장 하나로 정리해 줘.
"나는 [언제]마다 [입력]으로 [출력]을 만드는데, [병목] 때문에 [시간]이 걸린다. [확인 기준]이 맞으면 잘 된 것이다."
[확인 기준]이 숫자나 대조로 판정할 수 없는 말이면, 판정할 수 있게 바꾼 후보를 2개 제안해 줘.
후보를 제안했다면 내가 선택할 때까지 최종 문장으로 확정하지 마. 선택 후 미정 항목을 확인하고 최종 문장을 다시 써 줘.
내 답에 없는 내용은 지어내지 말고 [확인 필요]라고 표시해 줘.
```

> 💡 **생각할 시간** 결과를 보기 전에, 내 업무가 잘 됐는지 무엇으로 아는지(질문 4) 먼저 한 줄 적어 두세요. Claude가 정리한 확인 기준과 비교합니다.

후보가 나오면 하나나 둘을 선택하고, [확인 필요]로 남은 칸에 답합니다. 기준을 확정한 최종 문장만 메모장에 복사해 두세요. 실습 3에서 Project 지침에 붙여 넣습니다.

**문장이 정해지면 실습 3에 쓸 샘플 데이터를 준비합니다.** 먼저 내 업무 데이터의 등급을 봅니다. 익명화한 샘플을 미리 가져왔어도 등급은 다시 확인합니다.

이름, 사번, 연락처가 붙어 있으면 3단계입니다. 개인별 연봉, 평가, 징계, 건강 정보가 있으면 4단계입니다. 3단계 이상은 개인 계정 Claude에 넣지 않습니다. 가명 처리한 자료도 회사가 허용한 계정에서만 씁니다. 등급 기준은 [데이터 보안 기준](/guide/9-2/#1-데이터-등급-4단계)에 있습니다.

| 샘플 만드는 방법 | 이렇게 |
|---|---|
| 가상 샘플 만들기 | 열 이름만 알려 주고 Claude에게 가상 데이터를 만들게 한다. 실데이터가 Claude에 들어가지 않는다 |
| 내 데이터 줄이기 | 필요한 열만 남기고, 이름과 사번은 직원01처럼 바꾸고, 10~30행으로 줄인다. 가명 처리 방법은 [9-2](/guide/9-2/#3-가명-처리-요청-예시)에 있다 |
| 한결커머스 데이터 | 사례 카드에 딸린 샘플 파일을 그대로 쓴다 |

가상 샘플은 문제 정의 문장을 만든 같은 대화에서 아래 프롬프트로 만들고, [ ] 자리에 내 업무 파일의 열 이름을 적습니다. 자주 나오는 예외를 일부러 섞어 두면 실습 3에서 Claude가 그것을 잡는지 볼 수 있습니다.

```text
내 업무에 쓸 가상 샘플 데이터를 만들어 줘.
열: [열 이름을 쉼표로 나열]
행: 20개
이름은 실제 사람처럼 보이지 않게 직원01, 직원02처럼 써 줘.
내 업무에서 자주 나오는 예외(빈 칸, 형식이 다른 날짜, 같은 사람이 두 번 나오는 경우 같은 것)를 2~3개 섞고, 섞은 위치는 파일과 따로 대화에 적어 줘.
이 샘플로 내 문제 정의의 확인 기준을 대조할 수 있게, 필요한 비교값과 집계 기준도 따로 적어 줘. 회사의 실제 숫자는 쓰지 마.
CSV 파일로 만들어 줘.
```

만들어진 CSV 파일은 내려받아 둡니다. 실습 3에서 Project 대화에 올립니다.

20행 가상 샘플에는 회사 전체 인원이나 한결커머스의 전월 인원 305명을 그대로 대조값으로 쓰지 않습니다. 샘플에 맞는 비교값(예: 샘플 기준 전월 인원)은 Claude가 적어 준 값을 확인한 뒤, 메모장의 문제 정의 문장 아래에 함께 적어 둡니다. 중복 행을 섞었다면 행은 20개여도 직원은 20명보다 적을 수 있습니다.

## 4. 한 번 실행하고 검수하기

### 실습 3. 내 업무 Project에서 결과물 하나 만들기

**사용할 파일**: 실습 2에서 준비한 내 샘플 데이터

**먼저 Project를 만들고 지침을 넣습니다.** 문제 정의 문장은 실습 2에서 복사해 둔 것을 씁니다.

> 📌 **확인** 프로젝트를 만드는 버튼과 지침 칸의 이름은 플랜과 버전에 따라 다를 수 있습니다. Free 플랜은 Project를 5개까지 만듭니다. 코드 실행과 파일 생성 설정이 보이면 켜져 있는지 확인합니다. 항목이 없는 계정은 그대로 진행하고, 계산이나 파일 만들기가 실패하면 오류 문구를 강사에게 보여 주세요.

1. 사이드바 "프로젝트" > "새 프로젝트"를 누릅니다.
2. "무엇을 작업 중이신가요?" 칸에 업무 이름(예: "월말 입퇴사 현황")을, "어떤 목표를 달성하려고 하시나요?" 칸에 이 Project의 목표를 한 줄로 적습니다. 목표 칸은 지침과 다른 칸이고, "폴더 사용"은 고르지 않아도 됩니다. 공개 범위를 고르는 칸이 있으면(Team, Enterprise) "비공개"인지 확인한 뒤 "프로젝트 생성"을 누릅니다.
3. 생성된 화면 오른쪽 "지침" 옆 연필 아이콘(지침 편집)을 누르고, 아래 글을 붙여 넣은 뒤 [업무 이름], 문제 정의, 샘플 기준 비교값 자리를 채웁니다. "지침 저장"을 누릅니다.

```text
이 Project는 [업무 이름]을 위한 작업실이야.

문제 정의:
[실습 2에서 만든 문제 정의 문장 붙여 넣기]

샘플 기준 비교값:
[실습 2에서 메모해 둔 비교값과 집계 기준 붙여 넣기]

결과물을 만들 때 지킬 것:
- 숫자는 올린 파일을 직접 계산해서 써 줘.
- 무엇을 기준으로 셌는지, 어떤 열이나 문단을 근거로 했는지 밝혀 줘.
- 결과 끝에 문제 정의의 확인 기준과 샘플 기준 비교값으로 스스로 대조한 결과를 보여 줘.
- 파일에 없는 내용은 지어내지 말고 [확인 필요]라고 표시해 줘.
```

**그다음 샘플로 한 번 실행합니다.** 이번에는 Claude가 확인 기준으로 먼저 대조하게 하고, 나는 그중 하나만 다시 대조합니다.

Project 안에서 새 대화를 열고, 입력창의 "+" > "파일 또는 사진 추가"로 샘플을 올립니다. 매 대화에서 같은 자료를 쓰려면 Project의 "컨텍스트" > "파일 추가" > "기기에서 업로드"에 올려도 되고, 그때는 대화에 다시 첨부하지 않아도 됩니다. 컨텍스트에 지난달 파일과 이번 달 파일이 함께 있으면 프롬프트에 쓸 파일 이름을 적어 줍니다.

> 🖼️ **화면 확인** Project 화면 위쪽에 업무 이름이 보이고, 오른쪽 지침 칸에 문제 정의 문장이 보이면 맞게 왔습니다. 샘플은 대화의 첨부 파일이나 컨텍스트 중 내가 올린 곳에 보이는지 확인합니다. 아래는 컨텍스트에 올린 경우입니다.

![Project 지침에 문제 정의가 들어 있고, 컨텍스트에 가상 직원 명부가 표시됩니다.](/figures/claude-team-project-context.png)

아래를 붙여 넣고, [출력]은 내 문제 정의 문장의 출력으로 바꿉니다.

```text
올린 샘플로 [출력]을 만들어 줘.
지침의 확인 기준으로 대조한 결과를 마지막에 따로 보여 줘.
확실하지 않은 값은 [확인 필요]라고 표시해 줘.
```

> 💡 **생각할 시간** 결과를 보기 전에, 무엇을 확인하면 맞는지 알 수 있을지 하나만 정해 두세요.

**결과를 믿기 전에 확인 질문을 받습니다.** 같은 대화에서 아래 프롬프트를 보냅니다.

```text
방금 만든 결과를 그대로 보고에 써도 되는지 점검하고 싶어.
이 결과에서 (1) 내가 원본과 대조해야 할 숫자 (2) 네가 세운 가정 중 틀리면 결론이 바뀌는 것 (3) 빠졌을 수 있는 맥락을 각각 하나씩 질문으로 적어 줘.
```

**검수 3칸을 채웁니다.** 확인 질문 중 숫자 하나는 내가 원본과 직접 대조합니다. 가상 샘플에 예외를 섞었다면, Claude가 그 위치를 짚었는지도 봅니다.

| 맞은 것 | 틀린 것 | 빠진 것 |
|---|---|---|
| | | |

Claude가 올린 파일 밖에서 가져온 숫자는 출처와 기준 시점이 없으면 쓰지 않습니다.

**틀린 것이 있으면 증상을 그대로 말합니다.** [ ] 두 곳을 내가 찾은 내용으로 바꿉니다.

```text
[틀린 것]이 틀렸어. [내가 대조한 값]이 맞아.
왜 다르게 나왔는지 먼저 설명하고, 고친 결과를 다시 보여 줘.
```

두 번 말해도 고쳐지지 않으면 그 대화에서 계속 고치지 않습니다. 고칠 내용을 지침에 한 줄 더하고, 새 대화에서 다시 실행합니다.

**먼저 끝낸 분은** 지침에 한 줄을 더한 뒤 새 대화에서 같은 샘플로 다시 실행합니다. 두 번의 검수 3칸을 나란히 놓고 틀린 것이 줄었는지 봅니다. 이 실행이 숙제 기록표의 2차 줄이 됩니다.

**조별 공유.** 조 안에서 한 사람씩 1분 동안 두 가지만 말합니다. 하나는 문제 정의 문장, 다른 하나는 이번 실행에서 틀린 것 하나입니다. 틀린 것이 없었다면 직접 대조한 기준 하나를 말합니다. 다른 사람의 틀린 것을 들으면 내 결과에도 같은 것이 없는지 찾아봅니다.

## 도전 과제

실습을 먼저 끝낸 분이 이어서 해 볼 심화 과제입니다. 수업 뒤에 해도 됩니다.

### 도전 1. 확인 기준이 틀린 결과를 잡는지 시험하기

내 문제 정의의 확인 기준이 실제로 오류를 잡는지 시험합니다. 실습 2에서 만든 샘플 CSV를 복사해 한 행의 값을 일부러 바꿉니다. 날짜 하나를 다른 달로 바꾸거나, 숫자 하나에 0을 하나 더 붙이는 정도면 됩니다. 사본은 이름을 바꿔 두고(예: 샘플_오류.csv), 같은 Project의 새 대화에 올립니다. 실습 3의 프롬프트에서 "올린 샘플"을 사본 파일 이름으로 바꿔 보냅니다.

Claude가 확인 기준으로 대조한 결과에서 바꾼 행을 짚었다면 기준이 제 역할을 한 것입니다. 짚지 못했다면 확인 기준이 그 오류를 잡지 못하는 문장입니다. 기준을 고쳐 Project 지침에 다시 넣고 같은 사본으로 한 번 더 돌립니다.

### 도전 2. 같은 일을 Claude Code로 해 보기

Claude Code를 이미 쓰고 있다면 실습 3과 같은 일을 Claude Code에서 해 보고 결과를 비교합니다. Claude Code는 Pro 이상 플랜에서 씁니다.

내 가상 샘플만 넣은 새 폴더를 만들고, 그 폴더에서 Claude Code를 엽니다. 실데이터는 이 폴더에 넣지 않습니다. 아래의 [ ]를 채워 붙여 넣습니다.

```text
이 폴더의 [샘플 파일 이름]으로 [출력]을 만들어 줘. 파일은 읽기만 하고 고치지 마.
문제 정의: [실습 2에서 만든 문제 정의 문장]
숫자는 파일을 직접 계산하고, 무엇을 기준으로 셌는지 밝혀 줘. 결과 끝에 문제 정의의 확인 기준으로 대조한 결과를 보여 줘.
확실하지 않은 값은 [확인 필요]라고 표시해 줘.
```

Project에서 만든 결과와 나란히 놓고 검수 3칸을 각각 채웁니다. 숫자가 같은지, 어느 쪽이 기준을 더 분명하게 밝혔는지 봅니다.

## 숙제

같은 업무를 **2~3번 더 실행**하고, 매번 아래 기록표에 한 줄씩 적습니다. 표는 문서나 시트에 옮겨 두고 씁니다.

- 같은 Project 안에서 새 대화를 열어 실행합니다. 샘플은 같은 것도 되고, 행을 바꾼 새 샘플이면 더 좋습니다.
- 틀린 것을 고치려고 다시 설명한 말은 내가 쓴 문장 그대로 적습니다. 빠진 것도 틀린 것 칸에 함께 적습니다.
- 다음에도 같은 말을 해야 한다면 지침에 옮기고 O를 표시합니다.
- 실행할 때마다 실습 3의 확인 질문 프롬프트를 붙여 봅니다. 매번 같은 질문이 나오면 그 내용도 지침에 옮깁니다.
- 2회차에 이 기록이 스킬 재료가 됩니다. 틀린 것과 다시 설명한 것이 구체적일수록 스킬이 잘 만들어집니다.
- 2회차 Apps Script 실습과 3회차 보고문 초안 버튼에는 Claude Console(API 키를 만들고 결제하는 사이트)의 API 키가 필요합니다. 수업 전에 [Claude Console 가입하기](/guide/9-3/#claude-console-가입하기)를 보고 가입, 크레딧 결제, 월 지출 한도 설정까지 해 두면 좋습니다. 키는 수업에서 만듭니다.
