# 설치, 대화 요령, 용어

## 개요

준비물은 그것을 쓰는 회차 전에 갖추면 됩니다.

## 1. 설치와 계정 준비

### 언제 무엇을 준비하나

| 준비할 것 | 쓰는 때 | 플랜 조건 | 다 됐는지 확인하는 법 |
|---|---|---|---|
| [데스크톱 앱](#데스크톱-앱) | 1회차부터 | 전 플랜(Free는 Chat만) | 앱에 로그인하면 웹에서 쓰던 대화 목록이 보인다 |
| [Claude in Chrome](#claude-in-chrome) | 2회차 실습 | 유료 플랜 | 주소창 오른쪽에 고정한 Claude 아이콘을 누르면 Claude 창이 열린다 |
| [Claude Console 가입과 결제](#claude-console-가입하기) | 2회차 API 실습, 3회차 보고문 초안 버튼 | 구독 플랜과 별개 | platform.claude.com에 로그인되고, Settings > Billing에 크레딧 잔액과 월 지출 한도가 보인다 |
| [Claude Code](#claude-code-설치맥) | 3회차 | Pro 이상 | 터미널에 `claude --version`을 치면 버전 번호가 나온다 |
| [Node.js 22 이상](#nodejs-설치하기) | 3회차 | 플랜과 무관 | 터미널에 `node --version`을 치면 v22 이상이 나온다 |
| [Git](#git-확인하기) | 3회차 | 플랜과 무관 | 터미널에 `git --version`을 치면 버전 번호가 나온다 |
| [GitHub, Vercel 개인 계정](#github와-vercel-개인-계정-만들기) | 3회차 | 무료 | github.com과 vercel.com에 로그인된다 |

3회차에 처음 쓰는 네 가지(Claude Code, Node.js, Git, GitHub와 Vercel 계정)는 미리 한 번씩 시도해 보고, 막힌 화면은 오류 문구가 보이게 캡처해 두세요. 물어볼 때 빨리 풀립니다.

> 📌 **확인** 회사 PC는 설치나 브라우저 확장이, 회사 계정(Team, Enterprise)은 일부 기능이 막혀 있을 수 있습니다. 회사 IT 담당에게 먼저 확인하고, 허용되지 않으면 개인 PC로 실습합니다.

### 데스크톱 앱

1. [claude.ai/download](https://claude.ai/download)에서 내 운영체제용 설치 파일을 받습니다. macOS 11 이상, Windows 10 이상에서 됩니다.
2. 설치한 뒤 앱을 열고, 수업에 쓸 Claude 계정으로 로그인합니다.
3. 웹에서 쓰던 대화 목록이 앱에도 보이면 설치가 끝난 것입니다.

2회차에 내 PC 폴더를 Cowork에 연결할 때는 데스크톱 앱이 꼭 있어야 합니다. 내 화면에서 Chat과 Cowork를 어떻게 고르는지는 계정마다 다르고, 확인 방법은 [1-2](/guide/1-2/#실습-1-학습-설정-메모리-내-화면-유형-확인하기)에서 다룹니다.

### Claude in Chrome

Chrome 브라우저에서 Claude가 페이지를 읽고, 클릭하고, 입력하게 해 주는 확장 프로그램입니다. 유료 플랜에서만 쓰고, Edge 같은 다른 브라우저와 모바일에서는 쓸 수 없습니다.

1. Chrome 오른쪽 위 프로필 아이콘에서 실습용 프로필을 새로 만들고, 그 프로필 창을 엽니다. 회사 메일, 인사시스템, 금융 사이트가 로그인되지 않은 프로필이어야 합니다.
2. 그 창에서 [Chrome 웹 스토어의 Claude 페이지](https://chromewebstore.google.com/detail/claude/fcoeoabgfenejglbffodgkkbkcdhcgfn)를 엽니다.
3. "Add to Chrome"을 누릅니다.
4. Claude 계정으로 로그인합니다.
5. 주소창 오른쪽의 퍼즐 아이콘을 눌러 Claude를 고정합니다.
6. 요청하는 권한을 허용합니다. 고정한 Claude 아이콘을 눌러 Claude 창이 열리면 설치가 끝난 것입니다.

> ⚠️ **주의** 공식 도움말은 민감한 계정이 없는 별도 브라우저 프로필에서 쓰라고 권합니다. 확장 프로그램은 프로필마다 따로 설치되므로, 기본 프로필에 이미 설치했다면 실습용 프로필에 다시 설치합니다.

### Claude Console 가입하기

2회차 Apps Script 실습과 3회차 미니앱의 보고문 초안 버튼에서 쓰는 Claude API 키는 Claude 구독과 따로 운영되는 Claude Console에서 만듭니다. **가입과 크레딧 준비, 월 지출 한도는 미리 해 두면 좋습니다.** 키는 만들 때 한 번만 보이므로 수업에서 만들어 바로 넣습니다. 2회차는 시트의 스크립트 속성에, 3회차는 `.env.local` 파일에 넣습니다.

1. [platform.claude.com](https://platform.claude.com)을 엽니다. 예전 주소인 console.anthropic.com으로 들어가도 이 주소로 넘어갑니다.
2. 화면 안내에 따라 가입하고 로그인합니다.
3. 로그인한 화면이 보이면 가입이 끝난 것입니다.
4. 쓸 크레딧을 마련합니다. Max 플랜이라면 아래 "플랜에 붙는 크레딧"대로 포함 크레딧을 먼저 받고, Pro이거나 부족하면 Settings > Billing > "Buy credits"로 삽니다. 산 크레딧은 선불이고, 산 날부터 1년 뒤 만료되며 환불되지 않습니다. 최소 금액은 화면에서 확인합니다. 수업 실습에는 최소 금액이면 충분합니다.
5. 같은 화면의 "Spend limits"에서 월 지출 한도를 작게 겁니다. 코드가 잘못 돌아도 여기서 멈춥니다.

미리 확인해 둘 것이 두 가지 있습니다.

- **결제 수단**: 크레딧을 살 때는 해외 결제가 되는 카드가 있어야 합니다. 회사 카드라면 승인 절차가 필요한지 먼저 봅니다.
- **플랜에 붙는 크레딧**: Max 플랜에는 월 API 크레딧이 붙는데, claude.ai의 Settings > Billing에서 Console 조직을 연결해야 받습니다. Team 플랜이라면 조직에 붙는 API 크레딧으로 키를 받을 수 있는지 관리자에게 먼저 물어봅니다.

수업에서는 가상 데이터만 보내므로 개인 계정으로 가입해도 됩니다. 회사 업무에 쓸 키는 회사 정책에 따라 따로 만듭니다.

> 💰 **비용** API는 구독료와 별도로 쓴 만큼 냅니다. 2회차 설문 200건 분류가 2센트 안팎이고, 계산법은 2회차에서 다룹니다.

### Claude Code 설치(맥)

데스크톱 앱에도 Code가 들어 있어 따로 설치하지 않고 쓸 수 있습니다. 터미널에서 쓰려면 아래 순서로 설치합니다.

1. 터미널을 엽니다. Spotlight(⌘ + Space)에서 '터미널'을 검색하면 됩니다.
2. 아래 명령을 붙여 넣고 Enter를 누릅니다.

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

3. 설치가 끝나면 터미널 창을 닫고 새로 엽니다.
4. 아래 [설치를 확인하기](#설치를-확인하기)로 넘어갑니다.

### Claude Code 설치(윈도우)

Windows 10 1809 이상, 메모리(RAM) 4GB 이상이면 됩니다. 관리자 권한은 필요 없습니다. Git for Windows는 없어도 됩니다.

1. 시작 메뉴에서 'PowerShell'을 검색해 엽니다. 줄 앞이 `PS C:\`처럼 PS로 시작하면 PowerShell입니다.
2. 아래 명령을 붙여 넣고 Enter를 누릅니다.

```powershell
irm https://claude.ai/install.ps1 | iex
```

명령 프롬프트(CMD)를 쓴다면 아래 명령을 씁니다.

```cmd
curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd
```

> ⚠️ **주의** CMD용 명령을 PowerShell에 붙여 넣으면 "The token '&&' is not a valid statement separator" 오류가 납니다. 이 오류가 보이면 위의 PowerShell용 명령을 쓰세요.

3. 설치가 끝나면 창을 닫고 새로 엽니다.
4. 아래 [설치를 확인하기](#설치를-확인하기)로 넘어갑니다.

Homebrew(맥)나 WinGet(윈도우)을 이미 쓰고 있다면 아래 명령으로도 설치합니다. 이 두 방법은 자동으로 업데이트되지 않습니다.

```bash
brew install --cask claude-code
```

```powershell
winget install Anthropic.ClaudeCode
```

### 설치를 확인하기

새로 연 터미널(윈도우는 PowerShell)에 아래 명령을 입력합니다. 버전 번호가 나오면 설치된 것입니다.

```bash
claude --version
```

이어서 `claude`를 입력하면 Claude Code가 시작됩니다. 처음 시작할 때는 안내에 따라 Pro 이상 플랜의 Claude 계정으로 로그인합니다. 안내 화면은 버전에 따라 다를 수 있습니다.

### Node.js 설치하기

Node.js는 웹 앱의 서버 쪽 코드를 내 PC에서 돌리는 프로그램입니다. 3회차 미니앱에서 API 키를 숨겨 두고 Claude를 부르는 부분을 내 PC에서 시험할 때 씁니다. 버전은 22 이상이어야 합니다.

1. 터미널(윈도우는 PowerShell)에 아래 명령을 칩니다. `v22.12.0`처럼 v 뒤의 첫 숫자가 22 이상이면 이미 준비된 것입니다.

```bash
node --version
```

2. 명령을 찾을 수 없다고 나오거나 첫 숫자가 22보다 작으면 [nodejs.org](https://nodejs.org)에서 LTS 버전 설치 파일을 받아 실행하고, 안내대로 끝까지 넘깁니다.
3. 터미널을 닫고 새로 연 뒤 1번 명령을 다시 칩니다.

### Git 확인하기

Git은 파일이 바뀐 기록을 남기는 프로그램입니다. 3회차에 만든 앱을 GitHub에 올릴 때 Claude Code가 Git을 씁니다. Claude Code를 설치하는 데에는 필요 없습니다.

1. 터미널에 아래 명령을 칩니다. 버전 번호가 나오면 준비된 것입니다.

```bash
git --version
```

2. 맥에서 개발자 도구를 설치하라는 창이 뜨면 설치를 누르고, 끝날 때까지 몇 분 기다린 뒤 다시 칩니다.
3. 윈도우에서 "인식되지 않습니다"가 나오면 Git 공식 사이트 [git-scm.com](https://git-scm.com)에서 Git for Windows를 받아 설치합니다. 설치 화면의 선택지는 기본값 그대로 두고 넘깁니다.

### GitHub와 Vercel 개인 계정 만들기

3회차에 만든 앱을 GitHub에 올리고 Vercel로 배포하는 과정은 수업에서 강사 화면으로 보고, 수업 뒤에 각자 따라 합니다. 둘 다 회사 계정 말고 개인 계정으로 만듭니다.

| 서비스 | 하는 일 | 가입 | 알아 둘 것 |
|---|---|---|---|
| GitHub | 코드를 올려 두고 바뀐 기록을 관리하는 곳 | [github.com](https://github.com)에서 개인 계정 | 회사 GitHub 조직의 저장소는 Vercel 무료 플랜(Hobby)에 연결되지 않습니다. 개인 계정의 저장소를 씁니다 |
| Vercel | GitHub에 올린 앱을 인터넷 주소로 여는 곳 | [vercel.com](https://vercel.com)에서 Hobby(무료) 플랜 | Hobby는 비상업 개인용입니다. 실습과 시연에만 쓰고, 회사에서 실제로 운영할 도구는 회사 플랜이나 사내 인프라에 올립니다 |

### 설치가 안 될 때

| 증상 | 해결 |
|---|---|
| 윈도우에서 "The token '&&' is not a valid statement separator"가 뜬다 | CMD용 명령을 PowerShell에 넣은 것입니다. PowerShell용 명령(`irm ...`)을 씁니다 |
| `claude`, `node`, `git`을 입력하면 "command not found"나 "인식되지 않습니다"가 뜬다 | 터미널을 닫고 새로 연 뒤 다시 입력합니다. 그래도 안 되면 설치할 때 마지막에 나온 메시지를 그대로 Claude에게 붙여 넣고 묻습니다 |
| `node --version`의 첫 숫자가 22보다 작다 | nodejs.org에서 LTS 버전을 새로 설치하고 터미널을 새로 엽니다 |
| 회사 PC에서 다운로드나 설치가 막힌다 | 회사 보안 프로그램이나 정책 때문일 수 있습니다. IT 담당에게 확인하고, 허용되지 않으면 개인 PC로 실습합니다 |
| 로그인했는데 Claude Code를 쓸 수 없다고 나온다 | Free 플랜 계정인지 확인합니다. Claude Code는 Pro 이상에서 씁니다 |
| Claude in Chrome이 Edge에 설치되지 않는다 | Edge와 모바일은 지원하지 않습니다. Chrome을 씁니다 |
| Console에서 결제가 되지 않는다 | 해외 결제가 되는 카드인지 확인합니다. 회사 카드라면 승인 절차를 밟습니다. 2회차 Apps Script와 3회차 보고문 초안 버튼은 강사 화면으로 보고, 결제가 되면 그때 키를 만듭니다 |

## 2. 상황별 대화 요령

아래는 어느 도구에서나 통하는 요청 요령입니다. 도구별로 자주 생기는 증상과 해결은 [9-4 치트시트](/guide/9-4/)에 있습니다.

대괄호 칸이 있는 프롬프트는 메모장에서 먼저 채운 뒤 붙여 넣으세요. Claude Code 입력 칸에 여러 줄을 붙여 넣으면 중간을 고치기 어렵습니다.

### 시작이 막막할 때: 해법 대신 상황을 설명합니다

```text
나는 [회사 규모, 업종] 회사 인사팀에서 [직무] 일을 하는 사람이야.
[업무가 어떻게 돌아가는지 두세 줄]
지금은 [지금 어떻게 하고 있는지]
[무엇이 문제인지]

효율화할 수 있는 방법을 제안해 줘.
```

채워 쓰면 이렇게 됩니다.

```text
나는 직원 300명 규모 이커머스 회사 인사팀에서 노무 일을 하는 사람이야.
매월 초에 지난달 근태 파일을 내려받아 주 52시간을 넘긴 직원이 있는지 확인하고 팀장들에게 알려.
지금은 엑셀에서 직원마다 필터를 걸어 주별 근무시간을 더하고 있어.
교대 근무자가 많아서 계산이 자주 틀리고 반나절이 걸려.

효율화할 수 있는 방법을 제안해 줘.
```

"만들어 줘"가 아니라 **방법을 제안해 줘**로 끝냅니다. 무엇으로 만들지는 답을 보고 정합니다. 방법이 여러 개 나오면 "이 중에 가장 작게 시작할 수 있는 것은?"이라고 되물어 보세요.

### 방법을 골랐을 때: 작게 시작하고 기준을 함께 적습니다

```text
[파일 이름]의 열은 이렇게 생겼어.
[열 이름, 열 이름, ...]

[한 부서만 / 한 달 치만 / 한 사람만] 처리하는 것부터 해 줘.
- 계산 기준: [예: 근무시간 = 퇴근 - 출근 - 휴게 1시간]
- 결과에 이름과 이메일은 넣지 마
- 확실하지 않은 값은 [확인 필요]라고 표시해 줘
```

**작게 시작합니다.** 한 부서가 맞으면 같은 방법을 나머지 부서로 넓히면 됩니다. 계산 기준에는 수습 기간, 근무형태별 시간, 등급별 기준처럼 내가 당연하게 아는 회사 규칙을 적습니다. 개인정보를 빼는 줄과 [확인 필요] 줄은 항상 넣습니다.

보내기 전에 한 번 읽어 봅니다. 우리 회사를 전혀 모르는 신입에게 이 글만 줘도 일을 할 수 있을까요? 아니라면 빠진 규칙이 있는 것입니다.

### 무엇을 정해 줘야 할지 모를 때: 먼저 묻게 합니다

```text
아직 만들지 마. 결과를 가장 크게 바꿀 질문 3개만 먼저 나에게 물어봐 줘.
```

질문에 답한 내용이 그대로 다음 요청의 조건이 됩니다. 매번 같은 질문을 받는다면 그 답을 Project 지침이나 개인 지침에 옮겨 둡니다.

### 오류가 났을 때: 메시지를 그대로 붙여 넣습니다

```text
이런 오류가 나: [오류 메시지를 그대로 붙여 넣기]
무슨 뜻이고 어떻게 고치면 돼?
```

요약하지 말고 **그대로** 붙여 넣습니다. 메시지가 길어도 전부 넣으세요. 메시지에 실데이터(이름, 사번)가 섞여 있으면 그 부분만 지우고 붙여 넣습니다.

### 결과가 이상할 때: 보이는 증상을 그대로 말합니다

```text
부서별 표에서 '인사'와 '인사팀'이 다른 부서로 따로 잡혔어. 같은 부서로 합쳐 줘.
```

```text
인상률이 0.042처럼 나와. 4.2%처럼 퍼센트로 보여 줘.
```

```text
부서별 인원을 더한 값이 전체 인원과 안 맞아. 어느 부서에서 차이가 나는지 찾아 줘.
```

원인을 짐작해 덧붙이지 말고, 무엇이 보이는지와 어떻게 되기를 원하는지를 말합니다. 말로 설명하기 어려우면 화면을 캡처해 올리되, 캡처에 개인정보가 보이면 가린 뒤에 올립니다.

### 결과를 믿기 전에: 출처를 달고 대조하게 합니다

```text
표의 숫자마다 어느 파일의 어느 열(문서라면 어느 절)에서 왔는지 옆에 적어 줘.
두 자료의 숫자가 서로 맞지 않으면 어느 쪽이 맞는지 추측하지 말고 '불일치'로 표시해 줘.
```

```text
첨부한 두 파일에서 서로 어긋나는 값과 비어 있는 값을 찾아 줘.
표(항목, 파일 1의 값, 파일 2의 값, 어떤 문제인지)로 보여 주고, 어느 쪽이 맞는지는 판단하지 마.
```

두 번째 요청은 직원 명부와 근태 기록처럼 같은 사람이 두 파일에 나오는 일에 특히 잘 맞습니다.

### 화면을 만들 때: 위에서 아래로 묘사합니다

```text
맨 위에 숫자 세 개: 재직 인원, 이번 달 입사자, 이번 달 퇴사자.
그 아래에 부서별 인원 막대그래프.
맨 아래에 이번 달 퇴사자 표(사번, 부서, 퇴사일).

매월 첫 주에 인사팀장이 월간 회의 전에 보는 화면이야. 이렇게 만들어 줘.
```

코드 이야기는 한 마디도 하지 않습니다. 무엇이 보여야 하는지와 누가 언제 보는지만 적습니다.

### 다 된 것 같을 때: 한 번 더 돌려 봅니다

```text
같은 파일로 한 번 더 실행했더니 숫자가 달라졌어. 왜 다른지 설명하고, 매번 같은 결과가 나오게 계산 기준을 고정해 줘.
```

```text
한 번 더 실행했더니 이미 정리한 행이 또 추가됐어. 이미 처리한 행은 다시 처리하지 않게 해 줘.
```

**같은 입력으로 다시 실행해도 숫자가 같고 결과가 두 번 쌓이지 않아야 완성입니다.** 요약 문장은 실행마다 표현이 조금 달라질 수 있으니, 사실이 맞는지, 빠진 내용이 없는지, 형식이 기준에 맞는지를 봅니다. 그다음 결과에서 몇 건을 골라 원본과 직접 대조합니다. 맞은 것, 틀린 것, 빠진 것으로 나눠 보는 검수 방법은 [1-3](/guide/1-3/#검수-3칸)에서 다룹니다.

### 잘 안 통할 때 점검 순서

1. 요청이 결과를 묘사하고 있나요? 방법(함수, 코드)을 지시하고 있지는 않나요?
2. 완료 기준이나 출력 예시를 줬나요? "이렇게 나오면 돼" 세 줄이 설명 열 줄보다 낫습니다.
3. 한 번에 하나만 요청했나요? 세 가지를 한꺼번에 시키면 어디서 어긋났는지 찾기 어렵습니다.
4. 회사 규칙을 알려 줬나요? Claude는 우리 회사의 수습 기간, 근무형태, 평가 기준을 모릅니다.
5. 화면 문제인데 말로만 설명하고 있지는 않나요? 캡처를 올리세요.
6. 대화가 길어지며 엉뚱한 답이 반복되나요? 지금까지 정한 것을 요약해 달라고 한 뒤, 그 요약을 새 대화에 붙여 넣고 다시 시작합니다.

> 💰 **비용** 다른 일로 넘어갈 때는 새 대화를 엽니다. 대화가 길어지면 Claude가 앞의 내용까지 매번 함께 읽어서 사용량이 빨리 줄고, 답도 흔들립니다. Claude 앱과 Claude Code는 같은 사용 한도를 나눠 씁니다.

## 3. 용어

LLM, RAG, Agent는 [1-1](/guide/1-1/#2-핵심-개념-세-가지-llm-rag-agent), Project, Artifact, 커넥터, MCP는 [1-2](/guide/1-2/#4-방금-쓴-것들의-구조)에서 자세히 다룹니다.

어느 장에서 배웠는지 기억나지 않으면 메뉴 맨 위의 '교안 전체 검색' 칸에 용어를 넣어 보세요. 그 말이 나온 절을 찾아 줍니다.

### 1회차에 나오는 말

| 용어 | 뜻 |
|---|---|
| LLM | 많은 글을 학습해 다음에 올 말을 이어 쓰는 AI 모델. 그럴듯하게 틀릴 수 있어 검수가 필요합니다 |
| RAG | 답하기 전에 정해 둔 문서에서 관련 부분을 찾아, 그 내용을 근거로 답하게 하는 방식. 사내 규정 Q&A가 대표 예입니다 |
| Agent(에이전트) | 목표를 받으면 할 일을 스스로 나누고 파일, 브라우저, 커넥터 같은 도구를 써 가며 일을 이어 가는 AI. 일이 끝나거나 허락이 필요하면 멈추고 사람에게 묻습니다 |
| 프롬프트 | Claude에게 주는 지시문. 맥락, 원하는 것, 형식, 완료 기준을 담으면 결과가 좋아집니다 |
| 컨텍스트 | Claude가 답할 때 함께 보는 내용 전체. 지금까지의 대화, 올린 파일, 지침이 들어갑니다 |
| CSV | 쉼표로 칸을 나눈 표 파일. 엑셀이나 구글 시트로 엽니다 |
| 개인 지침 | 설정에 한 번 적어 두면 모든 새 대화에 붙는 내 지침. 설정 > 계정 > "Claude 지침"(영어 화면은 "Instructions for Claude")에 적습니다. 통합 화면은 Settings > General에 있습니다. 이름이 보이지 않으면 설정에서 "지침"이나 "instructions"가 들어간 칸을 찾습니다([1-2](/guide/1-2/#5-모든-대화에-붙는-내-지침-쓰기)) |
| Project | 업무별 작업실. 파일과 지침을 묶어 두고, 프로젝트마다 메모리가 따로 있습니다 |
| Project 지침 | 한 Project 안의 대화에만 붙는 지침. 그 업무의 문제 정의 문장과 기준을 적습니다([1-3](/guide/1-3/#실습-3-내-업무-project에서-결과물-하나-만들기)) |
| Artifact | 대화에서 만든 결과물. 문서, 슬라이드, 대시보드, 작은 도구가 있고 공유 범위를 정해 나눕니다 |
| 커넥터 | Gmail, Google Drive, Slack 같은 외부 서비스를 Claude에 연결하는 기능. 원본 서비스에서 내가 가진 권한까지만 접근합니다 |
| MCP | AI 도구를 외부 시스템에 연결하는 공통 규격. 직접 추가하는 커스텀 커넥터가 이 방식입니다. Claude Code에 추가하는 방법은 3회차에 다룹니다 |
| 메모리 | Claude가 이전 대화에서 알게 된 것을 기억해 다음 대화에 쓰는 기능 |
| 시크릿 채팅 | 대화 기록과 메모리에 남지 않고 학습에도 쓰이지 않는 대화. 서버에는 30일 보관됩니다 |
| 데이터 등급 | 데이터를 Claude에 넣어도 되는지 가르는 4단계. 1단계 공개, 2단계 사내, 3단계 개인정보, 4단계 민감, 기밀입니다([데이터 보안 기준](/guide/9-2/#1-데이터-등급-4단계)) |
| 가명 처리 | 이름, 사번 같은 값을 지우거나 다른 값으로 바꿔, 추가 정보 없이는 누구인지 알 수 없게 하는 것([데이터 보안 기준](/guide/9-2/#3-가명-처리-요청-예시)) |
| 문제 정의 문장 | 내 업무를 언제, 무엇으로, 무엇을 만드는지, 어디서 시간이 드는지, 무엇이 맞으면 잘 된 것인지 한 문장으로 쓴 것([1-3](/guide/1-3/#문제-정의-문장)) |
| 검수 3칸 | 결과를 맞은 것, 틀린 것, 빠진 것으로 나눠 적는 표([1-3](/guide/1-3/#검수-3칸)) |
| Claude Console | API 키를 만들고 크레딧과 지출 한도를 관리하는 사이트(platform.claude.com). 구독과 따로 결제합니다. 가입은 미리 해 둘 수 있고, 키 발급은 2회차와 3회차입니다 |
| Cowork | 파일을 읽고 만들며 여러 작업을 이어서 처리하는 Claude의 작업 방식. Pro, Max에서는 클라우드에서 돕니다. 실습은 2회차입니다 |
| Claude in Chrome | Chrome에서 Claude가 페이지를 읽고 클릭, 입력하는 확장 프로그램. 유료 플랜에서 쓰고, 실습은 2회차입니다 |
| Claude Code | 내 PC의 폴더에서 파일을 읽고 만들며 프로그램을 짓는 Claude. Pro 이상에서 쓰고, 실습은 3회차입니다 |
| API | 프로그램이 다른 프로그램에 일을 시키는 창구. 내 시트나 앱 안에서 Claude를 부르거나, 법령처럼 공개된 데이터를 가져올 때 씁니다. 실습은 2회차, 3-1 실습 2(법제처 API), 3-3 실습 1(보고문 초안 버튼)입니다 |
| 예약 작업 | 정해 둔 주기마다 Claude가 같은 일을 실행하게 하는 기능. 클라우드에서 돌아 PC가 꺼져 있어도 실행됩니다. 실습은 2회차입니다 |

| 권한 모드 | Claude가 파일을 고치거나 명령을 실행하기 전에 나에게 묻는 정도. Cowork에는 매번 승인받는 Manual과 알아서 진행하는 Auto가 있습니다. 3회차의 Claude Code에도 manual 모드와 auto 모드가 있어, 입력 칸 아래 상태 표시를 보고 Shift + Tab으로 바꿉니다 |

| API 키 | API를 쓸 때 나를 증명하는 비밀번호 같은 값. 공유하거나 화면 코드에 넣지 않습니다 |
| 지출 한도 | Console에서 정해 두는 한 달 사용 금액의 상한. 코드가 잘못 돌아도 여기서 멈춥니다 |
| 토큰 | AI가 글을 잘게 나눠 세는 단위. API 요금이 토큰 수로 매겨집니다 |
| Local routine | 데스크톱 앱의 Code에서 만드는 정기 실행. 내 PC가 켜져 있고 앱이 열려 있을 때만 돌아서, 내 PC 폴더의 파일이 필요한 정기 작업에 씁니다 |

### 3~4회차에 나오는 말

|---|---|
| 터미널 | 글자로 명령을 입력해 컴퓨터를 다루는 창. 맥은 터미널, 윈도우는 PowerShell을 씁니다(설치는 이 장 1절) |

| localhost | 내 PC 안에서만 열리는 주소. 미니앱을 내 PC에서 서버와 함께 켜 볼 때 씁니다 |
| 서버 함수 | 서버에서 도는 작은 프로그램. 3회차 보고문 초안 버튼에서 API 키를 숨겨 두고 Claude를 부릅니다 |
| JSON | 프로그램끼리 데이터를 주고받는 글자 형식. API 주소를 브라우저로 열면 이 형식의 원래 데이터가 보입니다(3-1 실습 2) |
| 로그인과 권한 | 로그인은 들어온 사람이 누구인지 확인하는 일, 권한은 그 사람이 무엇을 볼 수 있는지 정하는 일입니다([3-3](/guide/3-3/#3-로그인으로-볼-사람-정하기)) |
| 폐쇄망 | 인터넷이 막힌 사내망. 인터넷이 되는 PC에서 가짜 데이터로 만든 파일을 회사 반입 절차로 옮겨 씁니다([3-2](/guide/3-2/#5-사내망과-폐쇄망에서-쓰기)) |
