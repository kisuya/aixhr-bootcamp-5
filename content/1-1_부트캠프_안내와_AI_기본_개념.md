# 부트캠프 안내와 AI 기본 개념

## 1. 4주 동안 만드는 것

### 목표

목표는 하나입니다. **수료 후에도 회사에서 계속 쓰이는 HR 도구 하나**를 만듭니다.

한 번 쓰고 버리는 프롬프트가 아니라, 다음 달에도 같은 입력을 넣으면 같은 기준으로 결과가 나오는 도구입니다.

### 결과물 4유형

만들 도구는 아래 네 유형 중 하나입니다. 표의 예시와 수업 실습 파일은 가상 회사 한결커머스의 자료입니다. 직원이 약 300명인 생활용품 이커머스 회사이고, 소개는 [HR 사례 카드](/guide/9-1/#1-한결커머스와-실습-데이터)에 있습니다.

| 유형 | 이런 도구 | 한결커머스 예시 | 가까운 업무 |
|---|---|---|---|
| 대시보드와 분석 보고서 | 데이터를 넣으면 숫자와 차트가 정리되어 나온다 | 근태 파일을 고르면 부서별 근무시간과 주 52시간을 넘긴 직원이 보이는 화면 | 인력 현황, 근태, 보상 진단, 설문 분석 |
| 반복 문서와 계산 | 같은 양식의 문서를 사람 수만큼 만든다 | 평가 결과로 300명의 연봉 통지서를 한 번에 만들기 | 통지서, 인상 예산 계산, 면접 피드백 요약 |
| 정기 자동화 | 정해진 때에 알아서 돌고 결과를 보내 준다 | 매주 월요일 아침 고용노동부 보도자료 요약 받기 | 법령 동향, 수습 종료 알림, 입사 안내 메일, 채용 현황 리포트 |
| 사내 Q&A | 규정 문서를 근거로 질문에 답한다 | 취업규칙과 복리후생 규정에 답하는 Q&A | 규정 문의, 신규 입사자 FAQ |

### 4주 흐름

| 회차 | 주제 | 하는 일 | 숙제 |
|---|---|---|---|
| 1회차 10/14(수) | Claude 시작하기 | 설정과 커넥터, 내 업무 문제 정의, 첫 실행과 검수 | 같은 업무를 2~3번 더 실행하고 기록하기 |
| 2회차 10/20(화) | Claude와 함께 일하기 | 스킬과 예약 작업, Cowork로 파일 다루기, 브라우저와 화면 제어, Apps Script와 Claude API | 스킬 1개 실제 업무에 적용, 예약 작업 1개 설정, 3회차에 만들 도구 한 줄 정하기 |
| 3회차 10/27(화) | Claude Code | HR 미니앱을 만들고 AI 버튼 붙이기, 사내망과 폐쇄망에서 쓰기, 로그인과 배포, 내 도구의 첫 동작 만들기 | 내 도구를 하나씩 키우기 |
| 4회차 11/03(화) | 내 도구 만들기 | 각자 내 도구를 이어서 만들기, 원하는 사람만 만든 것 보여 주기 | 없음 |

> 💰 **비용** 이 과정은 각자의 Claude 유료 플랜으로 진행합니다. 2회차와 3회차에 쓰는 Claude API는 구독과 따로 계산합니다. Max는 플랜에 붙는 API 크레딧을 먼저 받고, Team은 조직 크레딧을 쓸 수 있는지 관리자에게 묻습니다. Pro이거나 크레딧이 부족하면 선불 크레딧을 삽니다. 3회차 팀장 보고문 초안 버튼에도 쓰니 미리 준비해 둡니다. 절차는 [9-3](/guide/9-3/#claude-console-가입하기)에 있습니다.

각 장 첫머리의 **이 장의 실습** 표에는 실습마다 수업에서 어떻게 하는지 적어 두었습니다. **함께 완성**은 수업 안에서 모두 끝까지 하는 실습입니다. **강사 시연**은 강사 화면으로 보고 수업 뒤에 따라 해도 되는 실습입니다. **선택 확장**은 먼저 끝낸 분이나 해당 직무에 있는 분이 하는 실습입니다.

### 수료 기준, 금요일 공유 시간, 스터디 조

오프라인 수업 4회 중 **2회 이상 빠지면 수료할 수 없습니다.**

매주 금요일 12:10~12:50(40분)에는 가볍게 진행상황을 공유하는 시간을 가집니다.

스터디 조는 실습에서 막힐 때 먼저 묻고, 숙제를 서로 보여 주는 모임입니다. 조 편성은 수업에서 안내합니다.

## 2. 핵심 개념 세 가지: LLM, RAG, Agent

세 개념을 통틀어 4주 내내 기억할 것은 하나입니다. **Claude는 그럴듯하게 틀릴 수 있어서, 사람이 검수해야 합니다.**

| 개념 | 한 줄 | 4주 동안 조심할 것 |
|---|---|---|
| LLM | 그럴듯한 다음 말을 이어 쓰는 모델 | 그럴듯하게 틀린다. 검수한다 |
| RAG | 찾아서 붙인 문서를 근거로 답하는 방식 | 못 찾거나 낡은 문서를 찾으면 틀린다. 출처를 밝히게 한다 |
| Agent | 도구를 쓰며 결과를 보고 다음 일을 스스로 정하는 방식 | 할 수 있는 일만큼 사고도 커진다. 멈출 곳을 정한다 |

![LLM, RAG, Agent의 관계. LLM에 자료 검색을 더하면 RAG, 도구와 반복을 더하면 Agent입니다. Agent도 필요하면 자료 검색을 씁니다.](/figures/1-1-concepts.svg)

### LLM: 다음 말을 예측하는 모델

LLM(대규모 언어 모델)은 아주 많은 글에서 배운 패턴과 지금 주어진 문맥을 바탕으로, "이 말 다음에 올 가장 그럴듯한 말"을 이어 쓰며 답을 만드는 모델입니다. Claude도 LLM입니다.

![학습할 때와 답할 때. 학습할 때는 많은 글로 모델 안의 패턴이 조정되고, 답할 때는 지금 주어진 문맥을 보고 다음 말을 이어 씁니다. 대화에 올린 파일은 답할 때의 문맥이고, 그 자리에서 모델을 다시 학습시키지 않습니다.](/figures/1-1-llm.svg)

대화에 올린 파일은 답할 때 읽는 문맥이고, 올리는 순간 모델이 다시 학습되지는 않습니다. 다만 개인 플랜에서 학습 사용이 켜져 있으면 대화가 나중의 학습에 쓰일 수 있으니, 설정은 [1-2](/guide/1-2/#실습-1-학습-설정-메모리-내-화면-유형-확인하기)에서 확인합니다.

다음 말을 이어 쓰는 방식이라, 정보가 부족하거나 근거를 잘못 고르면 사실과 다른 내용을 그럴듯하게 답할 수 있습니다. HR에서는 이런 장면으로 나타납니다.

| 그럴듯하게 틀리는 장면 | 확인하는 법 |
|---|---|
| 있지도 않은 법 조항 번호나 판례를 근거로 든다 | 국가법령정보센터에서 조문을 직접 연다 |
| 우리 회사 규정 대신 일반적인 관행으로 답한다 | 근거로 쓴 규정 문서와 조항을 밝히게 한다 |
| 표의 합계가 원자료 인원과 맞지 않는다 | 합계를 원자료 행 수와 대조한다 |
| 계산은 정확한데 무엇을 셀지 기준을 잘못 골랐다 | 무엇을 기준으로 셌는지 한 줄로 쓰게 한다 |

마지막 줄이 가장 잡기 어렵습니다. Claude가 코드를 짜서 계산하면 같은 입력에 늘 같은 결과가 나와서 맞아 보이기 때문입니다. 하지만 무엇을 셀지 잘못 고르면 계산이 정확해도 답은 틀립니다. 그래서 계산 규칙이 맞는지와 결과가 원자료와 맞는지는 따로 확인합니다.

### RAG: 찾아서 붙이고 답하기

RAG(검색 증강 생성)는 질문을 받으면 관련 문서를 먼저 찾아 붙이고, 그 내용을 근거로 답하는 방식입니다. 책을 펴 놓고 푸는 시험에 가깝습니다.

| 순서 | 하는 일 | HR 예 |
|---|---|---|
| 찾기 | 질문과 관련된 문서 조각을 찾는다 | "경조휴가는 며칠인가요?" → 취업규칙의 경조휴가 조항 |
| 붙이기 | 찾은 조각을 질문과 함께 모델에 넣는다 | 조항 원문 |
| 답하기 | 붙인 내용을 근거로 답한다 | 조항 번호를 붙여 답한다 |

![RAG가 답하는 순서. 질문을 받으면 규정 보관함에서 관련 부분을 찾고, 찾은 조항을 근거로 답을 만듭니다.](/figures/1-1-rag.svg)

관련 문서를 못 찾으면 답도 틀리고, 작년 규정 파일이 섞여 있으면 작년 기준으로 답합니다. 그래서 문서 이름에 날짜와 버전을 붙이고 낡은 파일은 뺍니다.

사내 Q&A 유형이 이 방식을 씁니다. Claude에서는 Project에 규정 파일을 올려 두고 그 파일을 근거로 답하게 합니다. 올린 자료가 적으면 Claude가 전부 읽고 답하고, 한 번에 읽을 수 있는 양의 한계에 가까워지면 필요한 부분만 찾아 읽는 RAG 방식으로 저절로 바뀝니다(유료 플랜). Project는 [1-3](/guide/1-3/#실습-3-내-업무-project에서-결과물-하나-만들기)에서 직접 만듭니다.

### Agent: 도구를 쓰며 스스로 되풀이하기

Agent(에이전트)는 LLM에 파일, 브라우저, 메일 같은 도구를 쥐여 준 방식입니다. 목표를 받으면 계획하고, 도구로 실행하고, 결과를 확인하고, 고치는 일을 스스로 되풀이합니다. 일이 끝나거나, 내 허락이 필요하거나, 더 나아갈 수 없으면 멈추고 사람에게 알립니다.

| 순서 | "다음 주 입사자 5명에게 보낼 온보딩 안내 메일 초안을 만들어 줘"를 맡기면 |
|---|---|
| 계획 | 입사자 명단 파일과 안내문 양식을 찾기로 한다 |
| 실행 | 명단을 읽고 사람마다 메일 초안을 쓴다 |
| 결과 확인 | 이름, 부서, 첫 출근일이 명단과 맞는지 다시 본다 |
| 수정 | 틀린 곳을 고치고 메일함에 초안으로 저장한다 |

![Agent가 일하는 순서. 다음 행동을 정하고, 도구로 실행하고, 결과를 확인하기를 되풀이합니다. 일이 끝나거나, 허락이 필요하거나, 막히면 멈추고 사람에게 알립니다.](/figures/1-1-agent.svg)

도구가 생기면 할 수 있는 일이 늘고, 사람이 정할 것도 늘어납니다. 무엇을 읽게 할지, 무엇을 바꾸거나 보내게 할지, 어디서 멈추고 확인받을지입니다. 위 예에서도 Claude는 초안 저장에서 멈추고, 보내기는 사람이 확인한 뒤에 합니다([자동화 안전 규칙](/guide/9-2/#4-자동화-안전-규칙-6개)).

## 3. Claude를 쓰는 세 방식

| 방식 | 무엇인가 | 기능 | HR 예 | 다루는 곳 |
|---|---|---|---|---|
| 앱 | 내가 묻고 결과를 받는다 | 채팅, Projects, Artifacts, 커넥터 | 규정 질문, 메일 요약, 입퇴사 현황 표 | 1회차 |
| 에이전트 기능 | 일을 맡기면 여러 작업을 스스로 이어서 처리한다 | Cowork, Claude in Chrome, 예약 작업, Claude Code | 근태 파일 정제, 통지서 300건, 매주 보도자료 요약 | 2회차, 3회차 |
| API | 내가 만든 도구 안에서 Claude를 부른다 | Claude API | 시트의 설문 응답을 한 줄씩 분류, 미니앱의 보고문 초안 버튼 | 2회차 Apps Script, 3회차 미니앱 |

앱과 에이전트 기능은 구독 플랜 안에서 쓰고, API는 구독과 별도로 쓴 만큼 냅니다.

> 📌 **확인** Free 플랜에서는 에이전트 기능(Cowork, Claude in Chrome, 예약 작업, Claude Code)을 쓸 수 없고, Projects는 5개까지 만듭니다. 에이전트 기능을 쓰는 2~3회차 실습 전에 내 플랜이 유료(Pro, Max, Team, Enterprise)인지 확인하세요. 데스크톱 앱과 Claude in Chrome, Claude Code 설치는 [9-3](/guide/9-3/#1-설치와-계정-준비)에 있습니다.

## 4. 맡기는 책임의 4단계

맡기는 책임은 묻기 → 맡기기 → 반복시키기 → 도구화 순서로 커집니다.

| 단계 | 하는 일 | HR 예 | 누가 결과를 확인하나 | 틀리면 무엇이 잘못되나 | 회차 |
|---|---|---|---|---|---|
| 묻기 | 질문하고 답을 읽는다 | "연차 사용 촉진 절차를 정리해 줘" | 내가 읽으면서 바로 | 내가 잘못 알고 넘어간다 | 지금까지 |
| 맡기기 | 파일과 기준을 주고 결과물을 받는다 | 직원 명부로 월말 입퇴사 현황 만들기 | 내가 결과물 전체를 검수 | 틀린 숫자가 보고서에 들어간다 | 1회차 |
| 반복시키기 | 같은 일을 같은 기준으로 매번 하게 한다 | 매월 입퇴사 현황, 매주 보도자료 요약 | 처음 2~3회는 전부, 그 뒤로는 확인 기준만 | 틀린 결과가 매번 쌓이고 늦게 알게 된다 | 2회차 |
| 도구화 | 다른 사람도 쓰는 도구로 만든다 | 근태 파일을 고르면 주 52시간 점검이 되는 사내 화면 | 만든 사람이 기준을 정하고, 쓰는 사람은 결과만 본다 | 여러 사람이 틀린 결과로 판단하고, 개인정보가 넓게 퍼질 수 있다 | 3~4회차 |

단계가 올라갈수록 사람이 결과를 덜 보게 됩니다. 그래서 **확인 기준은 앞 단계에서 미리 만들어 둡니다.**

### 어느 단계에서도 사람이 정하는 일

**한 사람에 대한 판단은 어느 단계에서도 사람이 정합니다.** 합격과 불합격, 평가 등급, 인상률, 근무 시간 배정, 징계가 여기에 들어갑니다. Claude가 초안을 낼 수는 있습니다. 그 초안을 바꿀 권한이 있는 사람이 검토한 뒤 정하고, 당사자에게는 AI를 썼다고 알립니다.

Anthropic 채용팀도 같은 선을 긋습니다. 지원자 안내 페이지에 Claude로 하는 일과 하지 않는 일을 나눠 공개해 두었습니다.

| Claude로 하는 일 | Claude로 하지 않는 일 |
|---|---|
| 채용 공고 작성, 면접 질문 개발, 지원자 안내 메일 초안, 채용 지표 분석, 면접 내용 받아쓰기, 소싱할 후보 찾기 | 채용 결정, 지원자 데이터로 Claude를 학습시키는 일 |

출처는 [Anthropic 지원자 AI 사용 안내](https://www.anthropic.com/candidate-ai-guidance)(2025-07-10 갱신)입니다.

평가 초안에도 같은 선이 있습니다. [Claude 공식 활용 예시](https://academy.claude.com/use-cases/eng-performance-reviews)의 평가 초안 프롬프트는 "등급은 쓰지 마(do not write the rating)"로 끝납니다.
