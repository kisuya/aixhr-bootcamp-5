# 에이전트로 일 맡기기

## 개요

1회차 숙제 기록표를 옆에 열어 두세요. 오늘 스킬의 판단 기준을 정할 때 참고할 자료입니다.

[1-1의 맡기는 책임 4단계](/guide/1-1/#4-맡기는-책임의-4단계)로 보면 오늘은 반복시키기 단계입니다. 같은 일을 같은 기준으로 매번 하게 하므로, 기준을 스킬과 지시문에 적어 둡니다.

**오늘 수업이 끝나면 세 가지가 남아야 합니다.**

1. 판단 기준이 들어간 스킬 1개: [2-2](/guide/2-2/#1-보상-진단-스킬-만들기)의 보상 진단 스킬이나 내 업무 스킬
2. 예약을 건 작업 1개와, 그 지시문을 한 번 실행해 확인한 결과: [2-2](/guide/2-2/#실습-2-예약-작업-하나-만들기)
3. Cowork 결과를 원본과 대조한 기록 1개: [2-3](/guide/2-3/#실습-2-근태-csv-세-개를-정제해-하나로-합치기)의 근태 정제 행 수 검산

**이 장의 실습**

| 실습 | 수업에서 |
|---|---|
| 실습 1. 내 기록표를 스킬 네 칸으로 나누기 | 선택 확장. 수업 뒤에 내 기록표로 합니다. 숙제를 하지 못했다면 이 장의 예시 기록표로 합니다 |

## 1. 일을 처리하는 수단 4가지

오늘부터는 Claude가 커넥터나 브라우저로 자료를 직접 가져와 처리하고, 결과를 파일이나 화면으로 남기는 일을 맡깁니다. 이때 쓰는 수단이 네 가지입니다.

| 수단 | 무엇을 하나 | 언제 쓰나(HR 예) | 한계 | 다루는 장 |
|---|---|---|---|---|
| 파일과 커넥터 | 올린 파일, 연결한 폴더, Gmail이나 Google Drive 같은 서비스의 데이터를 직접 읽고 쓴다 | 평가 결과 파일 점검, 지원서 메일 목록 정리, 월별 근태 파일 합치기 | 커넥터가 없는 사내 시스템에는 닿지 않는다. 내 계정 권한 안에서만 본다 | [2-2](/guide/2-2/), [2-3](/guide/2-3/) |
| 브라우저 | Claude in Chrome이나 Cowork 내장 브라우저로 웹페이지를 읽고, 누르고, 입력한다 | 고용노동부 보도자료 모으기, 공개 채용 공고의 복리후생 비교 | 느리다. 로그인, 팝업, 페이지 구조 변경에서 멈춘다. 페이지 안에 숨은 지시문이 있을 수 있다 | [2-4](/guide/2-4/#1-공개-사이트에서-정보-모으기) |
| 화면 제어 | 화면을 보면서 마우스와 키보드로 설치형 프로그램을 조작한다 | 내보내기 기능이 없는 설치형 급여, 근태 프로그램에서 보고서 받기 | 가장 느리고 잘 틀린다. 화면에 보이는 것이 모두 Claude에게 간다. Pro, Max 베타 전용 | [2-4](/guide/2-4/#2-화면-제어를-쓸-때와-쓰지-않을-때) (시연) |
| 예약 실행 | 위 수단으로 하는 일을 정해 둔 시각에 되풀이한다 | 매주 월요일 노동 관련 보도자료 요약 | 처음 몇 번은 결과를 직접 봐야 한다. 입력을 어디에 두느냐에 따라 돌지 않을 수 있다 | [2-2](/guide/2-2/#2-예약-작업으로-매주-돌리기) |

고를 때는 **커넥터로 되면 커넥터, 안 되면 브라우저, 그래도 안 되면 화면 제어를 씁니다.** 앞쪽일수록 대개 빠르고 덜 틀리며, Claude에게 보이는 범위도 좁아집니다. 실제로 어떤지는 서비스와 권한에 따라 다르니 결과로 확인합니다.

보는 범위는 보안과 바로 이어집니다. 커넥터는 내 계정이 볼 수 있는 데이터까지만 읽지만, 화면 제어는 그 순간 화면에 떠 있는 것을 모두 봅니다. 급여 프로그램 옆에 개인정보가 담긴 메일 창이 열려 있다면 그것까지 보입니다.

사내 시스템(ERP, 그룹웨어, 사내 메일)에 커넥터가 없고 브라우저나 화면 제어도 회사가 허용하지 않는다면, 그 환경에서 실행할 코드를 Claude에게 만들어 달라고 합니다. 외부 인터넷이 막힌 사내망 안의 일이나 매일 수백 건을 같은 규칙으로 처리하는 일도 이 방법을 검토합니다.

먼저 가짜 데이터로 코드를 만들어 시험하고, 실행은 회사가 허용한 PC나 사내 시스템 안에서 실제 데이터로 합니다. 엑셀 업무라면 매크로(VBA)로 받고, 정해진 시각에 돌리려면 Windows 작업 스케줄러에 겁니다. 외부와 연결하지 않는 매크로라면 데이터는 사내에만 머뭅니다. 회사가 실행 파일이나 매크로를 막아 두었다면 우회하지 말고 IT 담당에게 요청합니다.

오늘 [2-5](/guide/2-5/)에서는 Claude에게 코드를 받아 내 도구에 붙여 넣는 과정을 Google 시트의 Apps Script로 해 봅니다. 다만 이 코드는 Google 서버에서 돌고 설문 응답을 Claude API로 보내므로, 사내망 안에서 그대로 쓰는 방식은 아닙니다. 3회차에서는 Claude Code로 범위를 넓힙니다.

> 📌 **확인** Free 플랜은 Cowork, Claude in Chrome, 예약 작업, 화면 제어를 쓸 수 없습니다. 화면 제어는 Pro, Max의 베타 기능이라 Team, Enterprise에서는 쓸 수 없습니다. Free 플랜이라면 Cowork와 예약 작업 실습은 옆 사람과 짝을 지어 따라 합니다.

## 2. 반복 프롬프트를 스킬로 바꾸기

### 스킬은 업무 설명서입니다

같은 일을 2~3번 맡겨 보면 매번 같은 설명을 다시 하고, 같은 실수를 다시 고치게 됩니다. 이 설명과 고친 내용을 파일로 저장해 둔 것이 **스킬**입니다. 저장해 두면 Claude가 관련 요청을 받았을 때 스스로 꺼내 읽고 그 방식대로 일합니다.

스킬은 1회차에 쓴 지침 두 가지와 Claude가 읽는 때가 다릅니다.

| | 적은 곳 | Claude가 읽는 때 | 담는 것 |
|---|---|---|---|
| 개인 지침 | Settings([1-2](/guide/1-2/#실습-4-hr-담당자용-개인-지침-쓰기)) | 모든 대화에서 늘 | 내 직무, 한국 법 기준, 답하는 방식 |
| Project 지침 | 업무별 Project([1-3](/guide/1-3/#실습-3-내-업무-project에서-결과물-하나-만들기)) | 그 Project 안의 대화에서 늘 | 한 업무의 문제 정의 문장과 확인 기준 |
| 스킬 | Customize > Skills | 어느 대화에서든, 관련 요청이 왔을 때만 꺼내서 | 한 업무의 절차, 판단 기준, 예시 |

지침은 늘 붙어 있는 메모이고, 스킬은 그 일이 왔을 때 꺼내 읽는 설명서입니다. 스킬은 Project에 묶이지 않아서 Project 밖의 대화나 Cowork에서도 쓰입니다.

이번 수업에서는 스킬에 담을 내용을 네 칸으로 정리합니다. 첫 칸은 설명서 파일 맨 위의 설명(description)에, 나머지 세 칸은 본문에 적습니다.

| 칸 | 담는 것 | 파일에서의 위치 |
|---|---|---|
| 언제 쓰나 | 어떤 요청, 어떤 파일이 오면 이 스킬을 쓰는지 | 맨 위 description |
| 절차 | 일하는 순서 | 본문 |
| 판단 기준 | 맞고 틀림을 가르는 규칙, 예외 처리 | 본문 |
| 예시 | 잘 된 결과의 모양 | 본문 |

스킬은 폴더 하나이고, 그 안의 설명서 파일(이 교재에서는 SKILL.md로 부릅니다) 맨 위에 이름(name)과 설명(description)을 적습니다. Claude는 description을 보고 이 스킬을 꺼낼지 정합니다.

그래서 description에는 무엇을 하는지와 언제 쓰는지를 사람들이 실제로 쓰는 말로 적습니다. 비슷하지만 다른 일이 있다면 쓰지 않는 때도 한 줄 적어, 엉뚱한 요청에 꺼내지 않게 합니다. claude.ai 도움말은 description을 200자 안으로 쓰라고 안내하고, 이 교재도 그 기준을 따릅니다. 대화로 만든 스킬은 더 길어도 저장되는 경우가 있습니다.

### 숙제 기록표를 스킬로 옮기기

1회차 숙제 기록표의 칸이 스킬의 칸으로 그대로 옮겨 갑니다.

| 1회차에 적은 것 | 스킬에서 들어갈 칸 | 이유 |
|---|---|---|
| 문제 정의 문장의 [언제], [입력] | 언제 쓰나 | 이 일이 언제, 무엇을 받아 시작되는지가 곧 스킬을 꺼낼 조건이다 |
| 기록표의 "다시 설명한 것" | 절차 | 매번 다시 말했다면 Claude가 알아서 하지 않는 순서다 |
| 기록표의 "틀린 것" | 판단 기준 | 같은 실수를 막는 규칙이다 |
| 검수의 "맞은 것", 문제 정의 문장의 [확인 기준] | 예시 | 잘 된 결과의 모양을 보여 주면 다음에도 같은 기준으로 맞추기 쉽다 |
| 검수의 "빠진 것"(기록표에서는 "틀린 것" 칸에 함께 적음) | 절차 맨 끝의 확인 항목 | 다음에 빠뜨리지 않게 확인 항목으로 넣는다 |
| 기록표에서 "지침에 옮겼나"가 O인 줄 | 절차나 판단 기준 | Project 지침은 그 Project 안에서만 쓰인다. 스킬로 옮기면 다른 대화에서도 쓴다 |

이 중 가장 값진 칸은 판단 기준입니다. 절차는 Claude도 그럴듯하게 짜지만, **이 데이터에서 무엇이 함정인지는 그 일을 해 온 사람이 가장 잘 압니다.** 원하는 품질이 안 나오면 이 칸이 구체적인지 먼저 봅니다.

### 짧은 예시: 월말 입퇴사 현황 스킬

[1-3](/guide/1-3/#실습-1-9월-입퇴사-현황-만들기)에서 직원 명부로 9월 입퇴사 현황을 만들었습니다. 수업과 숙제에서 같은 일을 세 번 맡겼고, 기록표가 아래처럼 쌓였다고 해 봅니다.

| 차수 | 틀린 것 | 다시 설명한 것 |
|---|---|---|
| 1차 | 재직상태 열만 세서 재직 인원이 2명 많게 나왔다 | "퇴사일이 이미 지났으면 재직상태와 관계없이 퇴사로 세" |
| 2차 | 기준일을 묻지 않고 오늘 날짜로 셌다 | "기준일은 9월 30일이야" |
| 3차 | 소속을 합친 숫자만 냈고 검산이 없었다 | "본사와 물류센터로 나누고, 전월 재직 + 입사 - 퇴사로 맞춰 봐" |

이 기록을 옮기면 스킬은 이렇게 됩니다.

```markdown
---
name: monthly-headcount
description: 직원 명부로 월말 입퇴사 현황(월말 재직, 입사자, 퇴사자, 소속별)을 만든다. "입퇴사 현황", "월말 인원", "재직 인원 보고"를 요청하거나 직원 명부를 주며 인원을 세어 달라고 할 때 쓴다. 내년 인원 계획이나 채용 목표 계산에는 쓰지 않는다.
---

# 월말 입퇴사 현황

## 절차
1. 기준일을 확인한다. 요청에 없으면 먼저 묻는다.
2. 월말 재직, 그달 입사자, 그달 퇴사자를 센다.
3. 본사와 물류센터로 나눠 표를 만든다.
4. 검산한다. 전월 말 재직 + 입사자 - 퇴사자 = 월말 재직

## 판단 기준
- 재직 여부는 날짜로 판단한다. 기준일까지 입사했고, 퇴사일이 비어 있거나 기준일보다 뒤면 재직이다.
- 재직상태 열과 퇴사일이 어긋나는 행은 퇴사일을 따르고, 해당 사번을 따로 보여 준다.
- 확실하지 않은 값은 [확인 필요]로 표시한다.

## 예시
| 구분 | 본사 | 물류센터 | 합계 |
|---|---|---|---|
| 전월 말 재직 | 0 | 0 | 0 |
| 입사자 | 0 | 0 | 0 |
| 퇴사자 | 0 | 0 | 0 |
| 월말 재직 | 0 | 0 | 0 |
```

예시 표에는 실제 숫자를 넣지 않고 모양만 둡니다. 스킬은 다음 달에도 쓰는 설명서라서, 이번 달 데이터가 들어가면 다음 달에 틀린 기준이 됩니다.

스킬에 적은 판단 기준도 Claude가 매번 지킨다는 보장은 없습니다. 스킬을 만든 뒤에도 처음 2~3번은 결과 전체를, 그 뒤로는 확인 기준을 직접 대조하세요.

직무별로 내 업무 스킬을 만드는 프롬프트는 [2-2](/guide/2-2/#내-업무-스킬로-대신하기)에 있습니다.

### 실습 1. 내 기록표를 스킬 네 칸으로 나누기

**사용할 파일**: 1회차 숙제 기록표와 내 문제 정의 문장

숙제를 하지 못했다면 위 월말 입퇴사 현황 기록표로 해 봅니다. 문제 정의 문장은 [1-3](/guide/1-3/#문제-정의-문장)의 월말 입퇴사 현황 예시 문장을 붙여 넣습니다.

새 대화에 아래를 붙여 넣고, [문제 정의 문장 붙여 넣기]와 [기록표 붙여 넣기] 두 곳을 내 것으로 바꿉니다. 기록표에 동료 이름이나 개인 연봉이 있다면 그 내용을 지우거나 가상 값으로 바꿔 붙여 넣으세요. 실제 자료는 [9-2](/guide/9-2/#1-데이터-등급-4단계)의 기준대로 회사가 허용한 계정에서만 씁니다.

```text
아래는 1회차부터 같은 업무를 Claude에게 여러 번 맡기며 적은 기록이야. 아직 스킬 파일은 만들지 마.
업무: [문제 정의 문장 붙여 넣기]
기록표: [기록표 붙여 넣기]

이 기록을 스킬의 네 칸(언제 쓰나, 절차, 판단 기준, 예시)으로 나눠 표로 보여 줘.
- "틀린 것"은 "~이면 ~로 판단한다" 꼴의 판단 기준 문장으로 바꿔 줘
- "틀린 것" 칸에 빠진 것(요청했는데 없던 것)이 섞여 있으면 판단 기준 대신 절차 맨 끝의 확인 항목으로 옮겨 줘
- "다시 설명한 것"은 절차의 몇 번째 순서에 들어가는지 적어 줘
- 기록에 근거가 없어 채울 수 없는 칸은 지어내지 말고 [비어 있음]이라고 적어 줘
- 기록에 있는 실제 이름, 사번, 금액은 표에 옮기지 마
```

> 💡 **생각할 시간** 결과를 보기 전에, 네 칸 중 내 기록으로 가장 채우기 어려울 칸이 어디일지 하나 골라 두세요.

나온 표는 문서에 복사해 두세요. 수업 뒤 [2-2](/guide/2-2/#내-업무-스킬로-대신하기)의 내 업무 스킬을 만들거나 다듬을 때 재료로 붙여 넣습니다.

## 3. 대화와 Cowork 나눠 쓰기

대화(Chat)와 Cowork는 같은 앱 안에 있지만 맡기는 방식이 다릅니다.

| | 대화 | Cowork |
|---|---|---|
| 맡기는 방식 | 한 번 묻고 답을 받아 이어 간다 | 지시 하나로 여러 단계를 끝까지 맡긴다 |
| 맞는 일 | 질문, 초안, 요약, 판단을 같이 생각하기 | 파일을 읽고 정리해 다시 파일로 만드는, 여러 과정을 거치는 작업 |
| HR 예 | 징계 절차 문의 답변 초안, 평가 코멘트 다듬기 | 근태 CSV 세 개를 정제해 합치기, 연봉 통지서 300장 만들기 |
| 입력 | 붙여 넣거나 올린 파일, 커넥터 | 연결한 폴더의 파일, 커넥터, 브라우저 |
| 결과 | 대화 속 답, Artifact, 내려받는 파일 | 연결한 폴더에 저장되는 Excel, Word, PowerPoint, PDF 파일과 Artifact |
| 사람이 보는 때 | 답이 나올 때마다 | 시작할 때, 승인을 물을 때, 끝났을 때 |
| 오늘 다루는 장 | [2-2](/guide/2-2/#1-보상-진단-스킬-만들기)의 스킬, [2-5](/guide/2-5/) | [2-2](/guide/2-2/#2-예약-작업으로-매주-돌리기)의 예약 작업, [2-3](/guide/2-3/), [2-4](/guide/2-4/) |

Cowork는 처음 받은 지시 하나로 여러 작업을 이어 가므로, **무엇이 확인되면 끝인지를 지시에 담아야 합니다.** 1회차 문제 정의 문장에 적은 [확인 기준]을 지시에 넣으면 됩니다.

Cowork를 여는 방법은 [1-2](/guide/1-2/#실습-1-학습-설정-메모리-내-화면-유형-확인하기)에서 확인한 내 화면 유형에 따라 다릅니다. 통합 화면에서는 같은 메시지 상자에 그대로 맡기고, 분리 화면에서는 메시지 상자 왼쪽 아래에서 "Cowork"를 고른 뒤 맡깁니다. 실데이터를 맡기기 전에는 파일이 어디서 처리되는지를 다룬 [2-3](/guide/2-3/#1-시작-전에-파일이-어디서-처리되는지-확인하기) 1절을 먼저 읽으세요.
