# Claude Code가 필요한 일

## 개요

시작하기 전에 2회차 숙제를 짧게 돌아봅니다.

- **예약 작업**: [9-2](/guide/9-2/#4-자동화-안전-규칙-6개)의 안전 규칙 4번 "예약 작업은 처음 2~3회 결과를 직접 확인하고, 실패하면 알림 받을 사람을 정합니다"를 지켰나요?
- **스킬 적용**: 실제 업무에 써 보고 고친 판단 기준이 있나요?
- **만들 도구 한 줄**: 아래 1절의 표와 견주어 어떤 도구로 만들지 정합니다. 오늘 마지막 실습에서 이 도구의 첫 동작을 만듭니다.

[1-1의 맡기는 책임 4단계](/guide/1-1/#4-맡기는-책임의-4단계)로 보면 오늘은 도구화 단계입니다. 다른 사람도 쓰는 도구를 만드므로, 확인 기준을 먼저 정하고 데이터가 가는 길을 직접 확인합니다.

**오늘 수업이 끝나면 세 가지가 남아야 합니다.**

1. 내 PC에서 도는 근태 대시보드와, 손으로 대조한 한 사람의 주간 합계: [3-2](/guide/3-2/)
2. 집계 숫자만 서버로 보내는 팀장 보고문 초안 버튼: [3-3](/guide/3-3/#실습-1-팀장-보고문-초안-버튼-붙이기). Console 결제를 하지 못했다면 요청을 보내 "보내는 항목" 목록을 확인하는 데까지 합니다
3. 내 도구의 첫 동작: [3-3](/guide/3-3/#실습-4-내-도구의-첫-동작-만들기)의 실습 4

배포는 강사 시연으로 보고 수업 뒤에 따라 합니다. 사내망이나 폐쇄망에서 일한다면 [3-2](/guide/3-2/#5-사내망과-폐쇄망에서-쓰기)에서 만든 파일을 사내로 가져가는 방법을 봅니다.

**이 장의 실습**

| 실습 | 수업에서 |
|---|---|
| 실습 1. 부서별 인원 표를 HTML 파일로 만들기 | 함께 완성. 시간이 부족하면 5번(모드 바꾸기)까지 함께 하고, 나머지는 강사 화면으로 본 뒤 수업 뒤에 합니다 |
| 실습 2. 근로기준법 근로시간 조문 화면 만들기 | 함께 완성. 프롬프트 한 번으로 끝납니다. 실습 1이 밀리면 강사 화면으로 보고 수업 뒤에 합니다 |
| 먼저 끝낸 분: HR 문의 안내 페이지 만들기 | 선택 확장. 실습 2까지 먼저 끝낸 분이 합니다 |

## 1. 어떤 일에 어떤 도구를 쓰나

| 도구 | 이럴 때 쓴다 | 한결커머스 예 | 다루는 곳 |
|---|---|---|---|
| 대화와 스킬 | 내가 그때그때 시키고 결과를 바로 본다 | 보상 데이터를 받을 때마다 보상 진단 스킬로 점검 | [2-2](/guide/2-2/#1-보상-진단-스킬-만들기) |
| 예약 작업 | 정해 둔 때에 내가 없어도 돌고, 결과를 나에게 가져온다 | 매주 월요일 노동 관련 보도자료 요약 | [2-2](/guide/2-2/#2-예약-작업으로-매주-돌리기) |
| 플러그인 | 남이 만든 스킬 묶음을 설치해 바로 쓴다 | Data 플러그인으로 만든 보상 대시보드 HTML 파일 | [2-2](/guide/2-2/#5-플러그인으로-대시보드-만들기) |
| Artifact | 결과를 Claude 계정이 있는 동료와 화면으로 나눈다 | 이번 주 업무 정리 Docs 문서 | [1-2](/guide/1-2/#실습-3-이번-주-업무-정리-문서-만들기) |
| Claude Code | 아래 여섯 가지 중 하나라도 해당한다 | 근태 점검 대시보드와 팀장 보고문 초안 버튼 | [3-2](/guide/3-2/), [3-3](/guide/3-3/) |

**Claude Code가 필요한 여섯 가지 경우**

| 경우 | 이런 뜻입니다 | HR 예 |
|---|---|---|
| 사내 배포 | Claude 계정이 없는 사람도 주소 하나로 열어 써야 한다. 새 Artifact는 받는 사람도 Claude 계정에 로그인해야 열린다 | 물류센터 팀장들이 매주 여는 근태 현황 화면 |
| 로그인 | 누가 무엇을 볼 수 있는지 내가 정해야 한다([3-3](/guide/3-3/#3-로그인으로-볼-사람-정하기)) | 팀장은 자기 팀 근태만 본다 |
| 대량 처리 | 큰 데이터를 매번 같은 규칙으로 계산해야 한다. 한 번 검증한 계산 규칙을 코드로 고정해 두고 다시 쓴다 | 매달 6천 행이 넘는 근태 기록으로 주 52시간 점검 |
| 매일 웹 수집 | 여러 사이트에서 같은 항목을 매일 모아 쌓아야 한다. 한두 페이지 요약은 예약 작업으로 충분하다 | 노동 관련 보도자료와 행정해석을 매일 모아 주제별로 쌓기 |
| 도구 안에서 AI 호출 | 쓰는 사람이 버튼만 누르면 AI가 쓴 초안이나 요약이 나와야 한다 | 근태 대시보드에서 버튼을 누르면 팀장 보고문 초안이 나온다 |
| 폐쇄망에서 쓸 도구 | 인터넷이 막힌 사내 PC에서 Claude 없이 돌아야 한다. 인터넷이 되는 PC에서 가짜 데이터로 만들어 사내로 옮긴다([3-2](/guide/3-2/#5-사내망과-폐쇄망에서-쓰기)) | 폐쇄망 안에서 매달 여는 근태 점검 파일 |

2-2에서 플러그인으로 만든 대시보드는 만들 때의 데이터를 파일 안에 담은 한 장이라, 다음 달에는 새 파일로 다시 만들어야 합니다. 3-2에서 만드는 대시보드는 파일 안에 데이터를 담지 않고, 열 때마다 고른 CSV를 같은 계산 규칙으로 읽습니다. 매달 쓰는 도구라면 이쪽입니다.

Artifact도 Claude를 부를 수 있지만, 보는 사람 각자의 Claude 사용량을 쓰고 링크로 공개할 수 없습니다. Claude 계정이 없는 사람도 버튼만 누르게 하려면, 내 API 키로 Claude를 부르는 앱이 필요합니다.

> 💡 **팁** 여섯 가지 중 하나도 해당하지 않으면 Claude Code가 아니어도 됩니다. 스킬이나 Artifact로 더 빨리 끝나는 일을 굳이 앱으로 만들지 마세요.

## 2. 비개발자가 알아야 할 다섯 가지

| 개념 | 한 줄 설명 | HR로 비유하면 | 3회차에서 다시 나오는 곳 |
|---|---|---|---|
| 터미널 | 글자로 컴퓨터에 명령하는 창. 맥은 터미널, 윈도우는 PowerShell을 쓴다. Claude Code는 여기서 돌고, 내가 직접 치는 명령은 몇 개뿐이다 | 메뉴를 찾아 누르는 대신 담당자에게 한 줄로 요청하는 사내 메신저 | 이 장 실습 1 |
| 내 PC와 서버 | 내 PC는 내가 직접 쓰는 컴퓨터다. 서버는 늘 켜져 있어 다른 사람이나 프로그램의 요청을 받는 컴퓨터이고, 누가 들어올 수 있는지는 로그인과 접근 설정으로 정한다 | 내 책상 서랍 속 문서와, 출입증이 있어야 들어가는 사내 자료실 | [3-2](/guide/3-2/#1-만들-화면과-데이터가-가는-길)(브라우저 안에서만 처리), [3-3](/guide/3-3/)(서버 함수, 배포) |
| API와 비밀값 | API는 프로그램이 다른 프로그램에 일을 맡기는 방법이다. 비밀값(API 키)은 API를 쓸 때 나를 증명하는 비밀번호 같은 값이다 | 법인카드. 누가 긁든 회사 계좌에서 빠지니 번호를 아무 데나 적지 않는다 | 이 장 실습 2(가입 없이 부르는 법제처 API), [3-3](/guide/3-3/#실습-1-팀장-보고문-초안-버튼-붙이기) 실습 1(키를 코드 밖에 따로 두는 값인 환경변수에 넣기) |
| 배포 | 내 PC의 파일을 서버에 올려 주소를 만드는 일 | 결재가 끝난 문서를 게시판에 거는 일. 거는 순간 누가 볼 수 있는지가 정해진다 | [3-3](/guide/3-3/#실습-2-github에-올리고-vercel로-배포하기) 실습 2, 배포 전 보안 점검 |
| 로그인과 권한 | 로그인은 들어온 사람이 누구인지 확인하는 일이고, 권한은 그 사람이 무엇을 볼 수 있는지 정하는 일이다 | 출입증으로 건물에 들어오고, 출입증에 따라 열리는 층이 다르다 | [3-3](/guide/3-3/#3-로그인으로-볼-사람-정하기) 실습 3 |

**내 PC와 서버**는 보안과 바로 이어집니다. Claude Code 프로그램은 내 PC에서 돌지만, 읽은 파일 내용은 Anthropic 서버에 있는 Claude가 받아서 판단합니다. 개인 플랜(Pro, Max) 계정으로 쓰는 Claude Code도 [1-2](/guide/1-2/#실습-1-학습-설정-메모리-내-화면-유형-확인하기)에서 확인한 학습 데이터 설정을 따릅니다.

대화 기록은 내 PC의 `~/.claude/projects/` 폴더에도 평문으로 30일 남고, 여기에는 Claude가 읽은 파일 내용과 명령 결과가 그대로 들어갑니다. 그래서 실데이터 파일은 작업 폴더에 두지 않습니다. 실수로 읽혔다면 [9-2의 실수했을 때](/guide/9-2/#7-실수했을-때)를 따르고, 경로별 정리는 [데이터 보안 기준](/guide/9-2/#데이터가-가는-길)에 있습니다.

[2-2](/guide/2-2/#어디서-도는지-먼저-정하기)에서 본 실행 위치(클라우드와 내 PC)는 Claude가 일하는 곳입니다. 위 표의 "내 PC와 서버"에서 말하는 서버는 내가 만든 도구를 올려 두는 곳이라 서로 다릅니다.

## 3. 첫 명령 내리기

### 오늘 쓸 준비물 확인하기

설치 방법은 [9-3](/guide/9-3/#1-설치와-계정-준비)에 있습니다. 3회차 준비물이 다 됐는지 아래 표로 지금 확인하고, 안 된 것만 9-3을 보고 해결합니다. 먼저 터미널을 엽니다. 맥은 Spotlight(⌘ + Space)에서 '터미널'을, 윈도우는 시작 메뉴에서 'PowerShell'을 찾아 엽니다.

아래 표의 확인 명령을 하나씩 치고 Enter를 누릅니다.

| 준비물 | 확인하는 법 | 안 돼 있으면 | 쓰는 곳 |
|---|---|---|---|
| Claude Code | `claude --version`을 치면 버전 번호가 나온다 | 9-3 순서대로 설치합니다. 회사 PC라 막히면 데스크톱 앱의 Code로 합니다(표 아래 안내) | 이 장 실습 1부터 |
| Node.js 22 이상 | `node --version`을 치면 v22 이상이 나온다 | nodejs.org에서 LTS 버전을 받아 설치합니다 | [3-3](/guide/3-3/#실습-1-팀장-보고문-초안-버튼-붙이기) 실습 1 |
| Git | `git --version`을 치면 버전 번호가 나온다 | 9-3의 Git 확인하기를 따릅니다. 맥에서 개발자 도구를 설치하라는 창이 뜨면 설치를 누릅니다 | [3-3](/guide/3-3/#실습-2-github에-올리고-vercel로-배포하기) 실습 2(수업 뒤) |
| GitHub(코드를 올려 두고 바뀐 기록을 관리하는 곳), Vercel(GitHub에 올린 앱을 인터넷 주소로 여는 곳) 개인 계정 | github.com과 vercel.com에 로그인된다 | 3-2 실습에서 Claude Code를 기다리는 동안 가입합니다 | [3-3](/guide/3-3/#실습-2-github에-올리고-vercel로-배포하기) 실습 2(수업 뒤) |
| Claude Console 크레딧과 월 지출 한도 | platform.claude.com의 Settings > Billing에 크레딧 잔액과 한도가 보인다 | [9-3](/guide/9-3/#claude-console-가입하기)대로 결제합니다. 오늘 결제가 안 되면 3-3 실습 1은 1번 요청까지 하고, 실행 결과는 강사 화면으로 봅니다 | [3-3](/guide/3-3/#실습-1-팀장-보고문-초안-버튼-붙이기) 실습 1 |

> 💰 **비용** Claude Code는 Pro 이상 플랜에서 씁니다. 5시간 한도와 주간 한도가 있고, Claude 앱과 같은 한도를 나눠 씁니다. 수업 중에 Claude 앱에서 큰 작업을 함께 돌리지 마세요.

터미널용 Claude Code를 설치하지 못했다면 데스크톱 앱의 Code를 씁니다. 따로 설치하지 않고, 폴더를 고른 뒤 아래 프롬프트를 그대로 붙여 넣으면 됩니다. Free 플랜은 Claude Code를 쓸 수 없으니 옆 사람 화면으로 따라 보고, 일반 대화에 employees.csv를 올린 뒤 7번 요청을 넣어 결과를 비교해 보세요.

### 실습 1. 부서별 인원 표를 HTML 파일로 만들기

**사용할 파일**: [hangyeol_practice_data.zip](/practice-files/hangyeol_practice_data.zip)

한결커머스 실습 파일 묶음입니다. 이 실습에서는 그중 직원 명부 `employees.csv`(322행)를 씁니다. 이 파일에는 1회차에 만난 함정이 하나 있습니다.

실습이라 묶음 폴더에서 바로 엽니다. 실제 업무에서는 그 일에 필요한 파일만 든 새 폴더에서 열고, 실데이터 파일은 그 폴더에도 두지 않습니다. Claude Code는 폴더 안 파일을 읽는 순간 그 내용을 서버로 보내기 때문입니다(2절).

> ⚠️ **주의** 실습 파일은 모두 교육용 가상 데이터입니다. '한결커머스'와 직원, 지원자, 응답은 강의를 위해 만든 것이며 실제 회사나 사람과 관계가 없습니다. 내 회사 데이터로 옮길 때는 [데이터 보안 기준](/guide/9-2/#2-실데이터를-쓰기-전에-확인할-것)부터 확인하세요.

이 데이터가 진짜라면 이름과 사번이 붙은 인사 데이터라 3단계(개인정보)입니다.

강사가 먼저 화면으로 한 번 보여 줍니다. 따라 할 시간이 부족하면 5번(모드 바꾸기)까지만 내 PC에서 해 두세요. 나머지는 강사 화면으로 결과를 보고, 수업 뒤에 이어서 합니다. [3-2](/guide/3-2/)는 Claude Code가 내 PC에서 열리기만 하면 시작할 수 있습니다.

1. 위 링크로 zip 파일을 내려받아 압축을 풉니다. 나온 `hangyeol_practice_data` 폴더를 문서 폴더처럼 찾기 쉬운 곳에 옮겨 둡니다. 윈도우에서는 같은 이름의 폴더 안에 폴더가 하나 더 생길 수 있으니, 파일이 바로 보이는 안쪽 폴더를 옮깁니다.
2. 준비물을 확인할 때 연 터미널 창을 씁니다. 닫았다면 같은 방법으로 다시 엽니다.
3. `cd`와 빈칸 하나를 칩니다. `cd`는 터미널이 일하는 위치를 다른 폴더로 바꾸는 명령입니다. 이어서 `hangyeol_practice_data` 폴더를 터미널 창에 끌어다 놓으면 폴더 경로(폴더가 PC의 어디에 있는지 적은 주소)가 저절로 들어갑니다. Enter를 누른 뒤 줄 앞에 폴더 이름이 보이면 그 폴더로 들어간 것입니다.
4. `claude`를 치고 Enter를 누릅니다. 처음 여는 폴더라면 이 폴더를 믿고 작업해도 되는지 묻는 화면이 나올 수 있습니다. 내가 만든 실습 폴더가 맞으면 허용합니다.

```text
claude
```

명령을 찾을 수 없다("command not found", "인식되지 않습니다")고 나오면 터미널을 닫고 새로 연 뒤 3번부터 다시 합니다. 그래도 안 되면 [9-3의 설치가 안 될 때](/guide/9-3/#설치가-안-될-때)를 보고, 오늘은 데스크톱 앱의 Code로 이어 갑니다.

5. Claude Code가 열리면 입력 칸 아래의 상태 표시를 봅니다. "auto mode on"이면 Shift + Tab을 한 번 눌러 "manual mode on"으로 바꿉니다. 처음 시작하는 모드는 버전과 설정에 따라 다르니, 이미 "manual mode on"이면 그대로 둡니다.

auto 모드에서는 Claude가 묻지 않고 진행하고, 따로 도는 검사 모델이 위험해 보이는 행동만 막습니다. manual 모드에서는 파일을 만들거나 명령을 실행하기 전에 허락을 묻습니다. 데스크톱 앱의 Code에서는 모드 선택에서 Manual을 고릅니다.

6. 먼저 폴더를 설명하게 합니다. 아래 문장을 복사해 Claude Code 입력 칸에 붙여 넣고 Enter를 누릅니다.

```text
이 폴더에 어떤 파일이 있는지, 각 파일이 어떤 데이터인지 표로 설명해 줘.
파일은 읽기만 하고 고치지 마.
```

7. 이어서 부서별 재직 인원 표를 HTML 파일(브라우저로 여는 웹 페이지 파일)로 만들게 합니다. 같은 입력 칸에 붙여 넣습니다.

```text
employees.csv로 부서별 재직 인원 표를 만들어 dept_headcount.html 파일 하나로 저장해 줘.

- 재직자는 2026-09-30까지 입사했고 퇴사일이 비어 있거나 그 뒤인 사람으로 세어 줘.
- 소속(본사, 물류센터)별로 묶고, 소속별 소계와 전체 합계를 넣어 줘.
- 다 만들면 전체 합계가 몇 명인지 말해 주고, 파일을 브라우저로 열어 줘.
- 확실하지 않은 값은 [확인 필요]라고 표시해 줘.
```

허락을 묻는 화면이 뜨면 무엇을 하려는지 한 줄 읽고 허용합니다. 이 실습에서는 파일을 만들고 브라우저로 여는 일까지 허용해도 됩니다.

> 💡 **생각할 시간** 결과를 보기 전에, 무엇을 확인하면 맞는지 알 수 있을지 하나만 정해 두세요. 1회차에 같은 파일로 무엇을 확인했는지 떠올려 보세요.

브라우저가 열리지 않으면 그대로 묻습니다. "브라우저가 안 열렸어. 내가 직접 열려면 어디서 무엇을 누르면 돼?"

8. 터미널 창을 닫았다가 다시 엽니다. 3번처럼 같은 폴더로 옮긴 뒤 아래 명령을 치면 방금 대화가 다시 열립니다.

```text
claude --continue
```

다시 열면 처음 모드로 돌아갈 수 있습니다. 입력 칸 아래가 "auto mode on"이면 5번처럼 바꾼 뒤, 아래 요청을 붙여 넣습니다.

```text
방금 만든 표에 고용형태(정규직, 계약직) 열을 나눠 넣어 줘.
```

`claude --continue`(줄여서 `-c`)는 지금 폴더의 가장 최근 대화를 엽니다. 지난 대화를 목록에서 고르려면 `claude --resume`(줄여서 `-r`)을 치고, Claude Code 안에서는 `/resume`을 칩니다. 데스크톱 앱의 Code로 하는 분은 같은 대화에 이어서 요청합니다.

## 4. 공공 API로 법령 원문 가져오기

[2-5](/guide/2-5/)에서는 키를 받아 Claude API를 불렀습니다. 법제처 국가법령정보 API는 공식 가이드의 예시 값으로 가입 없이 불러 볼 수 있습니다. 이번 실습은 프롬프트 한 번으로 끝나고, 만든 화면이 API와 무엇을 주고받는지 직접 봅니다.

### 실습 2. 근로기준법 근로시간 조문 화면 만들기

**사용할 API**: [법제처 국가법령정보 공동활용](https://open.law.go.kr/)

법령 본문을 프로그램으로 받아 오는 정부 API입니다. 요청 주소에 신청해서 받은 인증값(OC)을 넣는데, 법제처 가이드의 예시 주소는 `test`를 씁니다. 실습은 이 값으로 합니다.

[3-2](/guide/3-2/#1-만들-화면과-데이터가-가는-길)에서 만드는 근태 대시보드의 주 52시간 기준은 근로기준법 제50조와 제53조에서 나옵니다. 그 조문을 원문으로 불러오는 화면을 만듭니다. 법령은 누구나 볼 수 있는 공개 정보라 1단계(공개)입니다.

1. 실습 1의 Claude Code 대화에 아래를 붙여 넣습니다.

```text
법제처 국가법령정보 API로 근로기준법의 근로시간 조문을 보여 주는 labor_law.html 파일 하나를 만들어 줘.
주 52시간 점검 도구를 만들기 전에 근거 조문을 원문으로 보려고 해.

- API는 https://www.law.go.kr/DRF/ 에 있고, 인증값 OC는 법제처 가이드의 샘플 값 test를 써 줘.
- 페이지를 열 때마다 API에서 근로기준법 현행 본문을 받아 와서, 제50조부터 제53조까지를 항과 호까지 그대로 보여 줘. 요약하거나 고치지 마.
- 맨 위에 법령의 시행일자를 보여 줘.
- 조문마다 국가법령정보센터 웹에서 그 조문을 여는 링크를 달아 줘.
- 화면 맨 아래에 실제로 부른 API 주소를 보여 줘.
- API에서 받지 못한 조문이나 항이 있으면 [확인 필요]라고 표시해 줘.
- 다 만들면 브라우저로 열어 줘.
```

Claude Code는 파일을 만들기 전에 `curl` 명령으로 API를 먼저 불러 볼 수 있습니다. 허락을 묻는 화면에서 주소에 `www.law.go.kr`이 들어 있으면 허용합니다.

> 💡 **생각할 시간** 결과를 보기 전에, 화면의 조문이 원문과 같은지 무엇으로 확인할지 하나 정해 두세요.

2. 브라우저에 조문이 나오면 제53조의 국가법령정보센터 링크를 눌러 같은 조문을 엽니다. 두 화면에서 항이 ①부터 ⑦까지 같은 개수인지, ⑦의 문장이 같은지 봅니다. 날짜 표기(`<신설 2021.1.5>`와 `<신설 2021. 1. 5.>`)는 띄어쓰기와 끝의 마침표만 다릅니다.
3. 화면 맨 아래의 API 주소를 복사해 브라우저 새 탭의 주소창에 붙여 넣고 엽니다. 한글과 영어, 숫자가 길게 이어진 글자가 나옵니다. API가 돌려준 원래 데이터이고, 이런 형식을 JSON이라고 부릅니다. Ctrl + F(맥은 ⌘ + F)로 `연장 근로의 제한`을 찾으면 화면의 제53조가 이 데이터 안에 있습니다. API를 부른다는 것은 이렇게 정해진 형식의 주소로 요청을 보내고 데이터를 받는 일입니다.

**이 화면이 법제처에 보낸 요청 내용은 주소에 다 보입니다.** 예시 값 `test`, 받을 자료 종류(법령), 근로기준법의 법령ID, 받을 형식(JSON)뿐입니다. `test`는 가이드에 공개된 값이라 숨길 것이 없습니다. [3-3](/guide/3-3/#실습-1-팀장-보고문-초안-버튼-붙이기)에서 부르는 Claude API의 키는 쓴 만큼 돈이 나가는 비밀값입니다. 이 파일처럼 브라우저에서 도는 코드에 두면 화면을 연 누구나 볼 수 있어서, 3-3에서는 키를 서버 함수에 두고 브라우저는 서버 함수만 부르게 만듭니다.

폐쇄망 PC에서는 이 화면이 조문을 불러오지 못합니다. 바깥 API를 부르는 도구는 인터넷이 되는 곳에서만 돕니다. [3-2](/guide/3-2/)의 대시보드는 바깥과 통신하지 않게 만들어 폐쇄망에서도 씁니다.

### 도전 1. 부서별 인원 표에 검산 열 넣기

실습 1의 표를 인원 현황 보고에 가깝게 키웁니다. 같은 Claude Code 대화에 아래를 붙여 넣습니다.

```text
dept_headcount.html의 표에 8월 말 재직, 9월 입사, 9월 퇴사 열을 더해 줘.
8월 말 재직은 2026-08-31까지 입사했고 퇴사일이 비어 있거나 그 뒤인 사람이야.
9월 입사와 9월 퇴사는 입사일과 퇴사일이 9월인 사람이야.
소속별 소계 행에 "8월 말 재직 + 9월 입사 − 9월 퇴사 = 9월 말 재직"이 맞는지 표시해 줘.
```

소계 행이 본사 121 + 2 − 1 = 122, 물류센터 184 + 6 − 4 = 186으로 맞으면 됩니다. [1-3](/guide/1-3/#실습-1-9월-입퇴사-현황-만들기)에서 손으로 한 검산을 화면이 대신하게 된 것입니다.
