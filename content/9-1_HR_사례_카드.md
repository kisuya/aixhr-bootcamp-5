## 1. 한결커머스와 실습 데이터

> ⚠️ **주의** 실습 파일은 모두 교육용 가상 데이터입니다. '한결커머스'와 직원, 지원자, 응답은 강의를 위해 만든 것이며 실제 회사나 사람과 관계가 없습니다. 내 회사 데이터로 옮길 때는 [데이터 보안 기준](/guide/9-2/#2-실데이터를-쓰기-전에-확인할-것)부터 확인하세요.

한결커머스는 생활용품을 파는 이커머스 회사입니다. 2026년 9월 말 기준 직원은 300명 남짓이고, 서울 본사와 경기 이천 물류센터 두 곳에서 일합니다. 물류센터 인원이 본사보다 많고, 물류센터에는 교대 근무가 있습니다.

| 항목 | 내용 |
|---|---|
| 본사(서울) | 경영지원, 인사, 재무, 개발, 상품기획, 마케팅, 고객경험 |
| 물류센터(경기 이천) | 입고, 출고, 재고관리, 배송관리 |
| 직급 | 사원, 주임, 대리, 과장, 차장, 부장 |
| 고용형태 | 정규직, 계약직(주로 물류센터) |
| 근무형태 | 본사는 주간(09:00~18:00, 휴게 12:00~13:00). 물류센터는 주간과 교대 3조(오전조 06:00~15:00, 오후조 14:00~23:00, 야간조 22:00~07:00) |
| 메일 도메인 | `hangyeol.example` (실재하지 않는 예시 도메인) |

근무 시간, 휴가, 수당, 복리후생, 겸업 같은 회사 규정은 [hangyeol_handbook.md](/practice-files/hangyeol_handbook.md)에 정리해 두었습니다.

### 카드의 칸

| 칸 | 뜻 |
|---|---|
| 직무 | 이 업무를 주로 맡는 HR 직무 |
| 업무 | 지금 사람이 하고 있는 일 |
| 입력 | 이 일에 들어가는 데이터나 문서 |
| 출력 | Claude와 함께 만들 결과물 |
| 만드는 경로 | 어느 회차에서 어떤 도구로 만드는지. 화살표는 앞 회차에서 만든 것을 다음 회차에서 키우는 순서입니다 |
| 데이터 등급 | 내 회사 실데이터로 할 때의 등급과 처리 방법 |
| 샘플 데이터 | 지금 바로 써 볼 수 있는 실습 파일 |
| 대조할 것 | 결과를 믿기 전에 무엇과 맞춰 보는지. 5분 안에 해 볼 수 있는 것만 적었습니다 |

카드 아래의 '바로 써 볼 첫 프롬프트'는 파일을 Claude에 올린 뒤 그대로 붙여 넣으세요.

### 카드를 내 문제로 옮기기

1. 내 직무와 가장 가까운 카드를 고릅니다. 꼭 맞는 카드가 없으면 입력과 출력의 모양이 비슷한 카드를 고르세요. 예를 들어 교육 이수 현황 집계는 명부에서 날짜 조건으로 골라 세는 일이라 '월말 입퇴사 현황'과 구조가 같습니다.
2. 카드의 문제 정의 문장 예시를 내 상황으로 고쳐 씁니다. 주기, 입력의 실제 이름, 지금 걸리는 시간, 확인 기준을 내 것으로 바꿉니다. 문장의 틀과 질문 4개는 [1-3](/guide/1-3/#1-문제-정의-질문-4개와-문장)에 있습니다.
3. 샘플 데이터로 첫 프롬프트를 실행하고, 카드의 '대조할 것'부터 해 봅니다. 그다음 결과를 맞은 것, 틀린 것, 빠진 것으로 나눠 적습니다.
4. 내 회사 데이터로 바꿀 때는 [데이터 보안 기준](/guide/9-2/#확인-목록)의 확인 목록을 먼저 봅니다. 평가, 인상률, 채용처럼 사람에 대한 판단이 걸린 카드는 [HR 결정에 AI를 쓸 때의 원칙](/guide/9-2/#5-hr-결정에-ai를-쓸-때의-원칙)도 함께 봅니다.

### 샘플 데이터가 없을 때

내 업무에 맞는 샘플이 없고 실데이터도 쓸 수 없으면, Claude에게 가상 데이터를 만들어 달라고 하세요.

```text
나는 [직무] 담당이야. [업무]를 연습하려고 하는데 실제 회사 데이터는 쓸 수 없어.
열은 [열 이름, 열 이름, ...]이고, [행 수]행 정도의 가상 데이터를 CSV로 만들어 줘.

- 이름은 흔한 성과 이름을 섞어 지어내고, 실제 인물이나 회사 이름은 쓰지 마
- 실무에서 자주 생기는 오류를 두세 개 섞어 넣고, 무엇을 어느 행에 넣었는지는 CSV와 따로 파일로 적어 줘
```

오류 목록 파일은 열지 말고 먼저 직접 찾아보세요.

| 샘플 데이터 | [employees.csv](/practice-files/employees.csv) |
| 대조할 것 | 지난달 말 재직 + 이번 달 입사 − 이번 달 퇴사가 이번 달 말 재직과 같은지 소속별로 계산합니다. 재직 여부를 어느 열로 셌는지 묻고, 같은 사실을 담은 두 열(재직상태와 퇴사일)이 서로 맞는지 따로 묻습니다. 같은 규칙을 [employees_boundary_sample.csv](/practice-files/employees_boundary_sample.csv) 3행에도 적용해, 기준일 뒤에 입사할 사람을 재직으로 세지 않는지 봅니다 |

1회차에 강사와 함께 만드는 예시와 같은 업무입니다. 경영진에게 보여 줄 인원 현황 대시보드로 키우려면 [3-1](/guide/3-1/#실습-1-부서별-인원-표를-html-파일로-만들기) 실습 1에서 만든 부서별 인원 표에서 출발합니다. [3-2](/guide/3-2/)처럼 뼈대, 기능, 실행 순서로 화면을 만들고, 이 카드의 대조할 것을 검수 기준으로 씁니다.

**바로 써 볼 첫 프롬프트**

```text
나는 한결커머스 노무 담당이야. 첨부한 attendance_2026-09.csv는 9월 근태 기록이야. 본사는 주간(09:00~18:00), 물류센터는 주간과 교대 3조(오전조 06:00~15:00, 오후조 14:00~23:00, 야간조 22:00~07:00)로 일해.

직원별로 주(월요일 시작) 근무시간 합계를 계산하고, 52시간을 넘긴 직원을 찾아 줘.
- 근무시간 = 퇴근 시각 - 출근 시각 - 휴게
- 휴게는 1시간이야. 휴가 열이 반차인 날(09:00~13:30 근무)은 휴게가 30분이라 실근무는 4시간이야
- 퇴근 시각이 출근 시각보다 이르면 다음 날 퇴근한 것으로 보고, 근무일은 출근한 날로 쳐
- 연차인 날은 출근과 퇴근이 비어 있어

형식: 52시간을 넘긴 직원 표(사번, 부서, 근무유형, 해당 주, 주간 합계)와 주마다 부서별 1인 평균 주간 근무시간 표.

완료 기준: 숫자는 파일을 직접 계산해서 써 줘. 넘긴 직원 중 한 명을 골라 날짜별 계산 과정을 보여 주고, 야간조 직원 한 명의 하루 계산도 보여 줘. 확실하지 않은 값은 [확인 필요]라고 표시해 줘.
```

**문제 정의 문장 예시**

| 대조할 것 | 한 안의 총 인상액을 직급별 합계로 다시 더해 같은지 봅니다. Excel 파일에서 칸을 눌러 값 대신 수식이 들어 있는지 봅니다. 2025연봉의 최솟값과 최댓값이 연봉으로 말이 되는 크기인지, 단위가 이상한 값은 없는지 봅니다 |

결과를 수식이 든 Excel로 받으면 칸을 눌러 계산을 직접 따라갈 수 있어 검산이 쉽습니다. 회사에서 Excel 안의 Claude 추가 기능을 쓸 수 있다면 Excel 안에서 해도 됩니다.

**바로 써 볼 첫 프롬프트**

```text
나는 한결커머스 보상 담당이야. 첨부한 comp_review_2026.csv의 2025연봉과 평가등급으로, 인상률 안에 따라 예산이 얼마나 드는지 미리 계산해 보려고 해.

두 안을 비교해 줘.
- 1안: S 7%, A 5%, B 3.5%, C 2%, D 0%
- 2안: S 9%, A 6%, B 3%, C 1%, D 0%

형식: 안별 총 인상액, 전체 평균 인상률, 직급별 인상액 합계를 나란히 놓은 표. 그 아래 두 안의 차이를 세 줄로.
같은 내용을 Excel 파일로도 만들어 줘. 등급별 인상률은 한 칸에 모아 두고, 나머지 칸은 그 칸을 참조하는 수식으로 만들어 안을 바꾸면 다시 계산되게 해 줘.

완료 기준: 계산에 쓴 인원, 2025연봉 합계, 2025연봉의 최솟값과 최댓값을 먼저 적어 줘. 확실하지 않은 값은 [확인 필요]라고 표시해 줘.
```

**문제 정의 문장 예시**

> 나는 매년 1월 인상률 안이 바뀔 때마다 엑셀 수식을 고쳐 예산 비교표를 다시 만드는데, 수식을 고치고 검산하는 일 때문에 안 하나에 반나절이 걸린다. 한 안의 총 인상액을 직급별 합계로 다시 더했을 때 같은 값이 나오면 잘 된 것이다.

### 카드 7. 평가 코멘트 초안

| 칸 | 내용 |
|---|---|
| 직무 | 평가보상(평가 제도 운영) |
| 업무 | 평가 시즌마다 팀장들이 쓸 평가 코멘트의 요청문과 양식을 만들어 배포하고, 근거 없이 쓴 코멘트를 돌려보냅니다 |
| 입력 | 회사 평가 기준(역량 정의), 팀원별 목표와 달성 기록, 1:1 면담 메모, 지난 평가의 성장 과제 |
| 출력 | 주장마다 근거 자료와 위치가 달린 역량별 코멘트 초안. 등급은 비어 있고, 근거가 모자란 곳에 [매니저 판단 필요]가 붙습니다 |
| 만드는 경로 | 1회차 Claude 시작하기(Project에서 가상 팀원 3명으로 초안 시험) → 2회차 Claude와 함께 일하기(평가 기준을 넣은 스킬로 만들어 팀장들에게 배포) |
| 데이터 등급 | 4단계 민감, 기밀(개인별 평가). 실데이터는 회사가 승인한 환경에서 팀장 본인이 다룹니다 |
| 샘플 데이터 | 없음. 아래 첫 번째 프롬프트로 가상 팀원 3명의 자료를 만듭니다 |
| 대조할 것 | 주장 세 개를 골라 괄호 속 근거를 열어 실제로 그 내용이 있는지 봅니다. 등급이나 등급을 짐작하게 하는 표현이 없는지, 근거가 모자란 역량에 [매니저 판단 필요]가 붙었는지 봅니다 |

평가 등급은 평가권자가 정합니다. [1-1](/guide/1-1/#어느-단계에서도-사람이-정하는-일)에서 소개한 Claude 공식 활용 예시의 평가 초안 프롬프트도 주장마다 근거를 달게 하고, "등급은 쓰지 마"로 끝납니다.

초안은 팀장이 근거를 확인하고 고쳐 쓴 뒤에 씁니다. 고치지 않은 초안이 그대로 평가가 되면 이용 정책이 말하는 고위험 사용이 됩니다([HR 결정에 AI를 쓸 때의 원칙](/guide/9-2/#5-hr-결정에-ai를-쓸-때의-원칙)).

**바로 써 볼 첫 프롬프트**

먼저 가상 자료를 만듭니다.

```text
평가 코멘트 초안을 연습하려고 해. 실제 직원 자료는 쓸 수 없어서 가상 자료가 필요해.
생활용품 이커머스 회사 마케팅팀 팀원 3명(가명 A, B, C)의 2026년 자료를 만들어 줘.

- 팀원별 연간 목표 3개와 달성 기록(숫자 포함)
- 팀원별 1:1 면담 메모 3~4건(날짜 포함)
- 팀원별 지난 평가의 성장 과제 1개
- 평가 기준: 역량 3개(성과, 협업, 성장)와 역량별 정의 한 줄

실제 인물이나 회사 이름은 쓰지 마. 한 명은 세 역량 중 하나의 근거가 거의 없게 만들어 줘.
```

그다음 같은 대화에서 초안을 받습니다.

```text
나는 한결커머스 평가보상 담당이야. 팀장들에게 나눠 줄 평가 코멘트 요청문을 시험하려고 해.
위 가상 자료로 팀원 A, B, C의 연간 평가 코멘트 초안을 역량별로 써 줘.

- 코멘트의 모든 주장 뒤에 근거 자료와 위치를 괄호로 달아 줘(예: 1:1 메모 2026-05-12)
- 근거가 모자란 역량은 지어내지 말고 [매니저 판단 필요]로 표시해 줘
- 등급은 쓰지 마. '최고 수준', '기대에 못 미침'처럼 등급을 짐작하게 하는 표현도 쓰지 마
- 평가 기준에 없는 기준을 만들지 마

형식: 팀원별로 역량 3개의 코멘트, 그 아래 매니저가 직접 채워야 할 곳 목록.

완료 기준: 팀원별로 근거를 단 주장 수와 [매니저 판단 필요] 수를 세어 줘. 확실하지 않은 내용은 [확인 필요]라고 표시해 줘.
```

**문제 정의 문장 예시**

> 나는 매년 1~2월 평가 시즌마다 팀장들이 낸 평가 코멘트를 모아 검토하는데, 근거 없이 쓴 코멘트를 골라 다시 써 달라고 돌려보내는 일 때문에 2주가 걸린다. 무작위로 고른 코멘트 10개의 주장마다 근거 자료가 달려 있고 등급을 짐작하게 하는 표현이 하나도 없으면 잘 된 것이다.

### 카드 8. 면접 피드백 요약

```text
나는 한결커머스 채용 담당이야. 첨부한 interview_notes.csv는 9월 면접관 메모 30건이야.

포지션별로 지원자 요약표를 만들어 줘.
- 지원번호, 포지션, 강점 한 줄, 우려 한 줄, 결과

- 결과는 파일의 결과 열을 그대로 옮기고, 새로 판단하거나 순위를 매기지 마
- 메모에 직무와 관계없는 개인 신상 이야기가 있으면 요약에 옮기지 말고, 해당 지원번호만 따로 알려 줘

형식: 포지션별 표. 그 아래 포지션별 합격, 불합격, 보류 건수.

완료 기준: 강점과 우려는 메모에 적힌 내용으로만 써 줘. 메모에 근거가 없는 평가는 넣지 마. 확실하지 않은 내용은 [확인 필요]라고 표시해 줘.
```

**문제 정의 문장 예시**

> 나는 채용 포지션마다 면접이 끝나면 면접관 메모를 모아 채용 위원회용 요약표를 만드는데, 면접관마다 다른 메모 형식을 맞추는 일 때문에 포지션 하나에 두 시간이 걸린다. 요약표의 강점과 우려가 모두 원래 메모에서 찾아지고 직무와 무관한 내용이 하나도 없으면 잘 된 것이다.

**문제 정의 문장 예시**

> 나는 매일 메신저로 들어오는 근무, 휴가, 복리후생 문의에 취업규칙을 찾아 답하는데, 같은 질문에 규정 위치를 다시 찾는 일 때문에 하루 한 시간이 걸린다. 자주 받는 질문 10개에 근거 절 번호와 함께 맞게 답하고, 문서에 없는 질문에는 확인이 필요하다고 답하면 잘 된 것이다.
