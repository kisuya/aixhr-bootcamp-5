# 미니앱 확장하고 배포하기

## 개요

3-2의 대시보드는 데이터가 브라우저 밖으로 나가지 않았습니다. 이 장에서는 AI 버튼이 화면의 집계 숫자를 서버로 보내고, 배포하면 앱이 서버에 올라갑니다. **데이터가 나가는 길이 생기므로, 보내는 것을 집계 숫자로 줄이고, 로그인으로 볼 사람을 정하고, 배포 전 보안 점검을 합니다.** 5절에서는 내 도구를 직접 만들기 시작합니다.

**폐쇄망에서 일하는 분은** 이 장의 AI 버튼과 배포를 사내에서 쓸 수 없습니다. 사내에서 쓸 결과물은 [3-2](/guide/3-2/#5-사내망과-폐쇄망에서-쓰기)의 파일입니다. 실습 1에서 이 파일이 바뀌므로, 시작하기 전에 `index.html`과 `README_반입.md`를 다른 폴더에 복사해 둡니다. 3-2 도전 과제로 기능을 더했다면 복사하기 전에 3-2 실습 4의 점검을 다시 합니다. 이 장은 가상 데이터로 따라 하며 구조를 익히고, 5절에서 내 도구를 만들 때는 3-2처럼 인터넷 없이 도는 파일로 만듭니다.

실습 1~3은 3-2의 `attendance-dashboard` 폴더에서 이어 합니다. Claude Code가 그 폴더에서 켜져 있으면 그대로 이어 갑니다. 닫았다면 터미널에서 그 폴더로 들어간 뒤 `claude --continue`로 앞 대화를 열고, 입력 칸 아래가 "manual mode on"인지 봅니다. "auto mode on"이면 Shift + Tab으로 바꿉니다. 실습 4만 새 폴더에서 합니다.

## 1. 팀장 보고문 초안 버튼 넣기

### 실습 1. 팀장 보고문 초안 버튼 붙이기

**사용할 파일**: [attendance_2026-09.csv](/practice-files/attendance_2026-09.csv)

> ⚠️ **주의** 실습 파일은 모두 교육용 가상 데이터입니다. '한결커머스'와 직원, 지원자, 응답은 강의를 위해 만든 것이며 실제 회사나 사람과 관계가 없습니다. 내 회사 데이터로 옮길 때는 [데이터 보안 기준](/guide/9-2/#2-실데이터를-쓰기-전에-확인할-것)부터 확인하세요.

노무 담당자는 대시보드를 본 뒤 팀장에게 짧게 보고합니다. 숫자는 대시보드가 이미 계산했으니, AI에는 그 숫자로 문장만 쓰게 합니다. 대시보드에 "보고문 초안" 버튼을 붙이고, 누르면 화면의 숫자로 쓴 5줄 이내의 초안이 나오게 합니다.

**AI에는 문장을 쓰는 데 필요한 숫자만 보냅니다.** 보고문에는 부서별 인원과 시간이 필요할 뿐, 누가 넘겼는지는 필요하지 않습니다. 그래서 원본 행과 사번, 이름은 지금처럼 브라우저 안에만 두고, 화면에 보이는 집계 숫자만 서버 함수(서버에서 도는 작은 프로그램)를 거쳐 Claude API로 보냅니다. 집계 숫자라도 실데이터라면 회사 승인 없이 보내지 않습니다.

원본 근태는 3단계(개인정보)이고, 서버로 보내는 부서별 집계는 2단계(사내)에 가깝습니다. 다만 한 명뿐인 부서의 숫자처럼 사람을 짐작할 수 있는 값은 3단계로 다룹니다.

이 실습에서 보내는 숫자 중 개발, 배송관리, 상품기획의 넘긴 인원(각 1명)과 가장 긴 주간 합계(한 사람의 값)가 여기에 해당합니다. 가상 데이터라 그대로 보내지만, 실데이터라면 1명인 부서는 다른 부서와 묶고 가장 긴 합계는 빼고 보냅니다. Claude API로 보낸 내용은 학습에 쓰이지 않고 원칙적으로 30일 안에 지워집니다([9-2](/guide/9-2/#데이터가-가는-길)).

**API 키는 화면 코드에 넣지 않습니다.** 화면 코드(`index.html`)는 페이지를 연 사람의 브라우저로 그대로 내려가서, 누구든 열어 키를 읽고 그 키로 내 크레딧을 쓸 수 있습니다. 그래서 안전 규칙 5번 "API 키는 공유하거나 화면 코드에 넣지 않고, 사용 한도를 설정합니다"를 지킵니다. 키는 서버 함수만 가집니다.

환경변수는 코드 밖에 따로 두는 값입니다. 내 PC에서는 `.env.local` 같은 파일에 두고, 이 파일이 GitHub에 올라가지 않게 `.gitignore`(GitHub에 올리지 않을 파일 목록)에 넣습니다. 배포한 서버에서는 Vercel 화면에 따로 넣습니다(실습 2).

| 위치 | 하는 일 | 키가 있나 |
|---|---|---|
| 화면(`index.html`) | 근태 파일을 읽어 계산하고, 버튼을 누르면 집계 숫자만 서버 함수로 보낸다 | X |
| 서버 함수 | 환경변수에서 키를 꺼내 Claude API를 부르고, 초안만 화면에 돌려준다 | O |
| Claude API | 받은 숫자로 보고문 초안을 쓴다 | |

키는 [2-5](/guide/2-5/#실습-2-api-키-발급하고-지출-한도-설정하기)에서 크레딧을 준비한 Console에서 만듭니다. 아직 크레딧이 없다면 1번 요청까지 해 두고, 실행 결과는 강사 화면으로 본 뒤 수업 뒤에 이어서 하세요. 한참 지나도 버튼이 되지 않으면 붙잡고 있지 말고 강사 화면으로 결과를 본 뒤 다음으로 넘어갑니다.

1. **요청**: 아래 프롬프트를 Claude Code에 붙여 넣습니다.

```text
대시보드에 "보고문 초안" 버튼을 붙여 줘. 노무 담당자가 이 화면을 보고 팀장에게 올릴 짧은 보고문 초안을 받는 용도야.

화면:
- 숫자 카드 아래에 "보고문 초안" 버튼. 누르면 그 아래 칸에 초안을 보여 주고, 복사 버튼을 둬.
- 초안 위에 "AI 초안입니다. 숫자를 화면과 대조한 뒤 쓰세요."라고 표시해 줘.
- 파일 버튼 옆 안내 문장을 "파일 원본은 이 브라우저 안에서만 읽습니다. 보고문 초안 버튼을 누르면 화면의 집계 숫자만 서버로 보냅니다"로 바꿔 줘.

AI 호출:
- Claude API를 쓰고 모델은 claude-haiku-5-5 (이 이름 그대로).
- API 키는 화면 코드에 넣지 마. 서버 쪽 함수가 환경변수 ANTHROPIC_API_KEY에서 키를 읽어 API를 부르고, 화면은 그 함수만 부르게.
- 내 PC에서는 키를 .env.local 파일에 두고, 이 파일이 .gitignore에 들어가게 해 줘. 파일은 키 자리만 비워서 만들고, 그 파일 내용은 읽지 마. 키는 내가 직접 넣을게.
- 서버로 보내는 것은 지금 화면에 보이는 집계 숫자뿐이야: 고른 주의 시작일, 읽은 행 수, 부서별 1인 평균 근무시간, 주 52시간을 넘긴 인원 수(전체와 부서별), 넘긴 사람 중 가장 긴 주간 합계, [확인 필요] 행 수. 사번, 이름, 원본 행은 보내지 마.
- 보내는 항목은 화면 코드의 한곳에 모아 두고, 다 만들면 그 목록을 나에게 보여 줘.

보고문 기준:
- 5줄 이내. 첫 줄에 기간과 결론, 그다음 숫자, 마지막 줄에 담당자가 확인할 것.
- 보낸 숫자만 써. 보내지 않은 숫자나 원인은 지어내지 말고, 원인이 필요하면 확인할 것으로 적어.
- 주 52시간을 넘긴 것을 법 위반이라고 단정하지 마. 탄력적 근로시간제나 특별연장근로 같은 예외가 적용되는지, 출퇴근 기록과 실제 근로시간이 같은지를 확인할 것으로 적어.

완료 기준:
- Vercel에 올릴 수 있는 구조로 만들어 줘. 내 PC에서는 Vercel에 로그인하지 않고 Node.js만으로 돌려 볼 수 있게 하고, 그 방법을 알려 줘.
- npm으로 패키지를 설치하지 말고 Node.js 기본 기능만으로 만들어 줘. Claude API는 fetch로 불러.
- 설치는 하지 않아도 필요한 설정 파일은 만들어 줘. 서버 함수에 import나 export를 쓰면 package.json에 "type": "module"을 넣어 줘.
- 확실하지 않은 부분은 [확인 필요]라고 표시해 줘.
```

2. **기다리는 동안 키 만들기**: Claude Code가 만드는 데 몇 분 걸립니다. 그동안 Console(platform.claude.com)의 Settings > API keys > "Create key"로 이 앱에만 쓸 키를 하나 더 만듭니다(이름 예: hr-miniapp). 앱마다 키를 나누면 문제가 생긴 키만 지울 수 있습니다. 키는 만들 때 한 번만 보이니 3번에서 붙여 넣을 때까지 그 화면을 열어 둡니다. 월 지출 한도가 걸려 있는지도 봅니다.

3. **키 넣기**: Claude Code가 끝나면 "`.env.local` 파일을 메모장(맥은 텍스트 편집기)으로 열어 줘"라고 요청합니다. 열린 파일의 `ANTHROPIC_API_KEY=` 뒤에 키를 붙여 넣고 저장합니다. **키를 Claude Code 대화창에 붙여 넣지 마세요.**

4. **실행**: Claude Code에 "내 PC에서 서버를 켜고 열 주소를 알려 줘"라고 요청합니다. Claude Code가 직접 켜 주거나, 터미널에 칠 명령을 알려 줍니다. 명령을 직접 칠 때는 터미널 창을 하나 더 열어 같은 폴더로 들어간 뒤 칩니다. 서버를 다시 켤 때는 Claude Code에 "서버를 다시 켜 줘"라고 요청합니다. 내가 다른 터미널 창에서 켰다면 그 창에서 Ctrl + C(맥도 control + C)로 끈 뒤 같은 명령을 다시 칩니다.

이제부터는 `index.html`을 더블클릭하지 않고, 알려 준 주소로 엽니다. `localhost`나 `127.0.0.1`로 시작하는 주소이고, 내 PC 안에서만 열립니다. 더블클릭으로 열면 서버 함수가 돌지 않아 버튼이 되지 않습니다. 9월 파일을 고르고, 주는 9월 14일 주로 둔 뒤 "보고문 초안"을 누릅니다.

> 📌 **확인** 서버가 켜지지 않으면 [3-1](/guide/3-1/#오늘-쓸-준비물-확인하기) 준비물의 Node.js 22 이상이 있는지 `node --version`으로 봅니다. 회사 PC에서 설치가 막히면 IT 담당에게 확인하고, 허용되지 않으면 개인 PC로 실습합니다.

> 💡 **생각할 시간** 초안을 읽기 전에, 초안의 숫자를 화면의 어디와 맞춰 볼지 하나만 정해 두세요.

**초안의 숫자를 화면과 대조합니다.** 숫자 카드, 막대그래프, 표에서 초안의 숫자를 하나씩 찾습니다. 화면에 없는 숫자가 있으면 보낸 숫자로 계산한 값인지(예: 부서별 인원의 합) 먼저 보고, 근거가 없으면 지어낸 것으로 보고 뺍니다. 원인을 단정한 문장과 법 위반이라고 단정한 문장도 고칠 대상입니다.

**버튼을 눌렀더니 오류가 나면**

서버를 켠 터미널 창과 브라우저 콘솔에 나온 오류를 그대로 붙여 넣습니다. 예를 들어 이런 오류입니다.

```text
보고문 초안 버튼을 눌렀더니 화면에 "실패"가 뜨고, 서버를 켠 터미널에 이 오류가 나와.
401 {"type":"error","error":{"type":"authentication_error","message":"invalid x-api-key"}}
원인을 한두 줄로 먼저 설명하고, 내가 할 일과 네가 고칠 일을 나눠서 알려 줘.
.env.local 파일 내용은 열지 마. 키 모양은 내가 직접 확인할게.
```

401은 키가 비었거나 잘못 들어갔다는 뜻입니다. 흔한 원인은 `.env.local`을 고친 뒤 서버를 다시 켜지 않은 것, 키 앞뒤에 빈칸이나 따옴표가 들어간 것입니다. Claude Code가 확인하겠다며 키를 보여 달라고 해도 붙여 넣지 말고, 키가 `sk-ant-`로 시작하는지만 직접 확인하세요.

3-2에서 외부 연결을 막는 설정(콘텐츠 보안 정책)을 넣었다면, 브라우저 콘솔에 "Content Security Policy"가 들어간 오류가 뜰 수 있습니다. 이때는 이 앱의 서버 함수로 가는 요청만 열어 달라고 하고, 바깥 주소를 모두 열어 달라고 하지 않습니다.

> 💰 **비용** 보고문 한 번은 입력과 출력을 합쳐 1천 토큰 안팎이라 `claude-haiku-5-5`로 열 번 눌러도 1센트에 못 미칩니다. 계산법과 지출 한도는 [2-5](/guide/2-5/#6-얼마나-들었나)와 같고, 실제 금액은 Console 사용량으로 확인합니다.

### 다른 예: 면접 메모 요약 화면

**사용할 파일**: [interview_notes.csv](/practice-files/interview_notes.csv)

채용 담당이라면 같은 서버 함수 구조로 면접 메모 요약 화면을 붙일 수 있습니다. 한결커머스 9월 면접 메모 30건이고, 열은 지원번호, 지원자, 포지션, 면접관, 면접일, 메모, 결과입니다. 이 파일에는 함정이 하나 있습니다.

이 데이터가 진짜라면 지원자 개인별 면접 평가라 4단계(민감, 기밀)입니다. 실습 1과 달리 이번에는 메모 원문이 서버로 갑니다. 그래서 보내는 것을 지원번호와 메모로 줄이고, 지원자 이름과 면접관 이름은 보내지 않습니다. 실데이터는 회사 승인 없이 넣지 않습니다.

**요약은 채용 담당자가 읽는 내부 초안이고, 합격과 불합격은 사람이 정합니다.** 지원자를 거르거나 순위를 매기는 데 AI를 쓰면 Anthropic 이용 정책이 말하는 고위험 사용이 되어, 사람의 검토와 당사자 고지가 필요합니다([1-1](/guide/1-1/#어느-단계에서도-사람이-정하는-일), [9-2](/guide/9-2/#5-hr-결정에-ai를-쓸-때의-원칙)). 아래 요청문의 요약 기준 첫 줄이 이 선을 지킵니다.

실습 1의 키와 서버 함수를 그대로 쓰므로, 같은 폴더의 Claude Code에 아래를 붙여 넣습니다.

```text
실습 1에서 만든 서버 함수 구조와 키를 그대로 써서, 면접 메모 요약 화면을 하나 더 붙여 줘. 채용 담당자가 면접관 메모를 빠르게 훑어보는 용도야.

화면:
- 맨 위 메뉴로 "근태 점검"과 "면접 메모 요약"을 오갈 수 있게.
- 면접 메모 CSV를 고르면 표로 보여 줘. 열: 지원번호,지원자,포지션,면접관,면접일,메모,결과
- 행마다 "요약" 버튼. 누르면 메모를 강점, 우려, 다음 단계 세 줄로 요약해 그 행 아래에 보여 줘.
- 서버로 보내는 것은 지원번호와 메모뿐이야. 지원자 이름과 면접관 이름은 보내지 마.

요약 기준:
- 메모에 적힌 내용만 줄여. 합격, 불합격, 점수, 순위는 네가 제안하지 말고, 다음 단계도 메모에 적힌 것만 옮겨.
- 메모에 나이, 혼인이나 출산 계획, 출신 지역, 가족, 외모처럼 직무와 무관한 내용이 있으면 요약에서 빼고, 그 행에 "판단 근거로 쓰면 안 되는 내용 포함" 경고를 띄워 줘. 무엇이 걸렸는지만 짧게(예: 나이).
- AI 판단과 따로, 메모에 나이, 결혼, 출산, 고향, 출신 같은 낱말이 있으면 코드에서도 경고를 띄워 줘. 둘 중 하나라도 걸리면 경고.

확실하지 않은 부분은 [확인 필요]라고 표시해 줘.
```

다 되면 서버를 다시 켜고, 면접 메모 화면에서 `hangyeol_practice_data` 폴더의 `interview_notes.csv`를 고른 뒤 몇 행의 요약 버튼을 눌러 봅니다.

채용절차법 제4조의3은 상시 30명 이상 사업장에 적용됩니다. 응시원서, 이력서, 자기소개서 같은 기초심사자료에 신체적 조건(용모, 키, 체중)이나 출신지역, 혼인여부, 재산 등을 요구하거나 수집하지 못하게 합니다. 면접 메모는 이 조문의 직접 대상이 아니지만, 이런 내용은 **직무와 무관하고 차별 소지가 있어 판단 근거로 쓰면 안 되는 정보입니다.** 요약 버튼이 경고를 띄우는 이유입니다.

## 2. GitHub에 올리고 배포하기

**수업에서는 강사 화면으로 과정을 보고, 수업 뒤에 아래 순서대로 따라 합니다.**

| | 실습(가상 데이터) | 실제 사내 운영 |
|---|---|---|
| 데이터 | 가상 데이터만 | 회사 승인을 받은 데이터 |
| GitHub | 내 개인 계정의 비공개 저장소 | 회사 GitHub 조직의 저장소 |
| 배포 | Vercel Hobby(무료, 비상업 개인용) | 회사가 계약한 플랜(Vercel Pro 등)이나 사내 인프라 |
| 보는 사람 | Vercel Authentication으로 막아 나만 | 회사 계정 로그인이나 회사 IP 제한으로 필요한 사람만([3절](/guide/3-3/#3-로그인으로-볼-사람-정하기)) |
| 누가 운영하나 | 나 | 개발팀이나 IT 담당과 함께 |

> ⚠️ **주의** Vercel Hobby는 약관상 비상업 개인용입니다. 급여를 받는 직원이 만든 회사 업무 도구도 상업적 이용에 들어가므로, 실제 업무 도구를 개인 Hobby 계정으로 운영하지 않습니다. Hobby는 GitHub 조직이 소유한 저장소에 연결되지 않고 비밀번호 보호도 쓸 수 없습니다.

### 실습 2. GitHub에 올리고 Vercel로 배포하기

GitHub 계정(github.com)과 Vercel 계정(vercel.com, 개인 Hobby)이 필요합니다. 3회차 준비물로 가입해 두지 않았다면 따라 하기 전에 가입합니다.

1. **GitHub에 올리기**: GitHub에서는 앱 폴더 하나를 저장소라고 부릅니다. 올라갈 파일을 먼저 보고 올리도록 아래를 Claude Code에 붙여 넣습니다.

```text
이 폴더를 Git으로 관리하게 하고, 내 GitHub 개인 계정에 비공개 저장소 hr-miniapp으로 올려 줘.
- 올리기 전에 .gitignore에 .env.local과 CSV 파일이 들어 있는지 보여 줘.
- 올라갈 파일 목록을 먼저 보여 주고 내 확인을 받아.
- GitHub 로그인이 필요하면 브라우저로 로그인하는 방법을 알려 줘. 로그인은 내가 직접 하고, 토큰이나 비밀번호를 이 대화에 붙여 넣지는 않을게.
```

**GitHub에 올리다가 막히면** 화면에 뜬 창이나 오류를 그대로 보여 줍니다. 맥에서 처음 Git을 쓰면 개발자 도구를 설치하라는 창이 뜰 수 있습니다. 설치를 누르고 끝날 때까지 몇 분 기다린 뒤 같은 요청을 다시 합니다. 윈도우에서 Git이 없다고 나오면 Claude Code에 설치 방법을 묻습니다.

2. **Vercel에 연결하기**: Vercel 대시보드에서 "New Project"를 누릅니다. 목록에 `hr-miniapp`이 없으면 Vercel이 내 GitHub 저장소를 읽도록 허용하는 화면에서 이 저장소에 접근을 허용합니다. `hr-miniapp`을 고른 뒤 설정 화면의 Environment Variables에 이름 `ANTHROPIC_API_KEY`, 값에 키를 넣고 "Deploy"를 누릅니다. 키는 Claude Code에 "`.env.local` 파일을 메모장(맥은 텍스트 편집기)으로 열어 줘"라고 해서 연 파일에서 복사해 이 화면에 바로 붙여 넣고, 대화창이나 메신저를 거치지 않습니다.

3. **접근 막기**: 배포가 끝나면 프로젝트 설정의 Deployment Protection에서 Vercel Authentication을 켜고, 범위는 **All Deployments**를 고른 뒤 저장합니다. 다른 선택지인 Standard Protection은 프로덕션(실제로 쓰는 배포 주소)을 막지 않습니다. 배포 주소를 시크릿 창(로그인 정보 없이 여는 브라우저 창)으로 열어 Vercel 로그인 화면이 나오는지 확인합니다. 공유 링크(Shareable Link)는 만들지 않습니다. 배포 화면의 Share에서 "Anyone with the link"를 고르면 만들어지고, 링크를 받은 사람은 로그인 없이 열 수 있습니다.

4. **배포한 앱 확인하기**: 내 브라우저(Vercel에 로그인된 창)에서 배포 주소를 열고, 9월 근태 파일을 고르고 주는 9월 14일 주로 둔 뒤, 주 52시간을 넘긴 직원 7명이 나오는지, 보고문 초안 버튼이 되는지 봅니다.

5. **고치고 다시 올리기**: 이후로는 Claude Code에 "고친 내용을 커밋하고 GitHub에 올려 줘"라고 하면 됩니다. 커밋은 바뀐 내용을 기록으로 남기는 일입니다. 이 저장소에 새로 올라갈 때마다 Vercel이 새로 배포합니다.

> 📌 **확인** Vercel 화면의 메뉴 이름은 바뀔 수 있습니다. GitHub 로그인 방식은 PC 환경마다 다릅니다. 막히면 오류 문장이나 화면을 그대로 Claude Code에 보여 주세요.

**내 PC에서는 되는데 배포한 앱에서 보고문 버튼만 안 되면** Vercel에 키를 넣지 않았거나, 넣은 뒤 다시 배포하지 않은 경우가 많습니다. 둘 다 했는데도 안 되면 브라우저 콘솔과 Vercel 프로젝트의 Logs 화면에 나온 오류를 Claude Code에 보여 주고, 서버 함수의 위치와 `package.json` 설정을 확인해 달라고 합니다. 키 값은 붙여 넣지 않습니다.

**사내 배포는 개발팀과 함께 합니다.** 실제로 회사에서 쓰려면 이 저장소를 개발팀이나 IT 담당에게 넘겨 회사 플랜이나 사내 인프라에 올립니다. 넘길 때 아래를 함께 주면 이야기가 빨라집니다.

- 무엇을 하는 도구인지 한 줄, 누가 얼마나 자주 쓰는지
- 데이터가 가는 길: 근태 원본은 브라우저 안에서만, 보고문 버튼은 집계 숫자만 서버 함수를 거쳐 Claude API로
- 누가 무엇을 볼 수 있어야 하는지(실습 3의 점검 결과)
- 필요한 환경변수 이름(`ANTHROPIC_API_KEY`). 값은 넘기지 않습니다
- 직접 대조한 검수 결과(주 52시간을 넘긴 직원 7명, 한 사람의 주간 합계 58.40시간, 보고문 초안의 숫자 대조)

<details>

1번에서 Claude Code가 보여 주는 올라갈 파일 목록에는 화면 파일, 서버 함수 파일, 내 PC에서 켜는 서버 파일, 설정 파일, `.gitignore`만 있어야 합니다. `.env.local`이나 `.csv` 파일이 목록에 있으면 올리지 말고 "이 파일은 빼고 .gitignore에 넣어 줘"라고 요청합니다. 3-2 실습 4에서 만든 `README_반입.md`가 보이면, 보고문 버튼을 붙이기 전의 설명이라 지금 앱과 맞지 않습니다. 빼거나 지금 구조에 맞게 고쳐 달라고 합니다.

## 3. 로그인으로 볼 사람 정하기

배포한 앱은 막지 않으면 주소만 알면 누구나 열 수 있습니다. 실습 2의 3번에서 Vercel Authentication을 켠 이유입니다. 근태처럼 개인 기록을 다루는 도구는 들어온 사람이 누구인지 확인하고(로그인), 그 사람이 볼 수 있는 것만 보여 줘야(권한) 합니다. 둘은 다른 일입니다. 로그인은 출입증으로 건물에 들어오는 일이고, 권한은 출입증에 따라 열리는 층이 다른 일입니다.

### 주소에 문 달기

가장 먼저 할 일은 배포 주소 자체를 아무나 열지 못하게 막는 것입니다. Vercel에서는 아래 방법을 씁니다.

| 방법 | 플랜 | 열 수 있는 사람 | 쓰는 곳 |
|---|---|---|---|
| Vercel Authentication | 모든 플랜, 무료 | Vercel 계정으로 로그인했고 접근 권한을 받은 사람. Hobby는 나 말고 외부 사용자 1명까지 | 실습과 시연. 직원 대부분은 Vercel 계정이 없어 사내 운영에는 맞지 않는다 |
| 비밀번호 보호 | Pro는 프로젝트당 월 $20, Hobby는 쓸 수 없음 | 비밀번호를 아는 사람 누구나 | 비밀번호 하나를 여럿이 나눠 쓰므로, 퇴사자나 담당이 바뀐 사람을 막기 어렵다 |
| Passport | Enterprise | 회사 계정(SSO)으로 로그인한 사람 | 실제 사내 운영. IT 담당이 회사 계정 시스템과 연결한다 |
| Trusted IPs | Enterprise | 회사 IP에서 접속한 사람 | 사내망 안에서만 열리게 할 때 |

> ⚠️ **주의** 공유 링크(Shareable Link)는 Vercel Authentication을 건너뜁니다. 링크를 받은 사람은 로그인 없이 열고, 링크가 회사 밖으로 전달되면 누구나 열 수 있습니다. 개인 기록을 다루는 도구에는 만들지 않습니다.

막지 않은 주소는 데이터만의 문제가 아닙니다. 주소를 아는 사람 누구나 보고문 버튼을 눌러 내 크레딧을 쓸 수 있습니다.

### 앱 안의 로그인과 권한

"팀장은 자기 팀 근태만 본다"는 규칙은 주소의 문으로는 정할 수 없습니다. 문을 통과한 사람은 모두 같은 화면을 보기 때문입니다. 앱이 로그인한 사람을 알아보고, 서버가 그 사람 팀의 데이터만 내려 줘야 합니다. 세 가지만 기억합니다.

1. **로그인은 직접 만들지 않습니다.** 회사 계정(SSO)에 붙이고, 어떤 방식을 쓸지는 IT 담당이 정합니다. 화면 코드에 비밀번호를 적어 두고 비교하는 로그인은 개발자 도구를 열면 비밀번호가 그대로 보입니다.
2. **화면에서 숨기는 것은 권한이 아닙니다.** 브라우저로 내려간 데이터는 개발자 도구로 모두 볼 수 있습니다. 볼 권한이 없는 데이터는 서버가 처음부터 내려 주지 않아야 합니다.
3. **데이터를 어디에 두느냐가 로그인이 필요한지를 정합니다.** 3-2 대시보드처럼 각자 자기 PC의 파일을 고르는 도구는 로그인이 필요 없고, 파일을 둔 폴더의 권한이 그 역할을 합니다. 여러 사람의 데이터를 서버에 모아 두는 순간부터 로그인과 권한이 필요합니다.

### 실습 3. 로그인 없이 누가 무엇을 보는지 점검하기

배포 주소를 막지 않았다고 가정하고, 지금 앱에서 누가 무엇을 볼 수 있는지 Claude Code에 점검하게 합니다. 팀장별 권한이 필요할 때 IT 담당에게 가져갈 질문도 정리합니다. 같은 Claude Code 대화에 붙여 넣습니다.

```text
이 앱의 로그인과 권한을 점검해 줘. 코드는 고치지 말고 결과만 표로 알려 줘.
1. 배포 주소를 막지 않았다고 가정하면, 로그인 없이 누가 무엇을 볼 수 있고 무엇을 할 수 있는지
2. 화면에서만 숨기고 실제로는 브라우저로 내려가는 데이터가 있는지
3. 코드 안에 비밀번호나 키를 직접 적어 두고 비교하는 부분이 있는지

그다음, 물류센터 팀장마다 자기 팀 근태만 보게 하려면 무엇이 필요한지 정리해 줘.
- 로그인은 회사 계정(SSO)에 붙인다고 가정해.
- 우리 회사 IT 담당에게 물어야 할 질문을 목록으로 만들어 줘.
- 아직 만들지는 마.
```

<details>
<summary>정답 예시 보기</summary>

**1~3번은 이렇게 나오면 맞습니다.** 1번은 배포 주소를 막지 않았을 때의 결과입니다. 실습 2처럼 막았다면 로그인하지 않은 사람은 Vercel이 막습니다.

| 화면에서만 숨긴 데이터 | 없다. 화면에 내려가는 데이터는 사용자가 고른 파일뿐이다 |

**팀장별 권한에 필요한 것**은 대체로 이런 목록입니다. 근태 데이터를 회사가 승인한 서버 저장소에 두기, 회사 계정 로그인, 누가 어느 팀의 팀장인지 알려 줄 정보, 서버에서 팀으로 거른 데이터만 내려 주기, 누가 언제 무엇을 봤는지 남기는 기록입니다.

**IT 담당에게 물을 질문**의 예입니다.

- 이 앱을 회사 계정 로그인(SSO)에 등록할 수 있는지, 어떤 방식을 쓰는지
- 팀장과 팀 정보를 어디서 받아 올 수 있는지
- 근태 데이터를 둘 수 있는 승인된 저장소가 어디인지
- 앱을 올릴 회사 플랜이나 사내 인프라가 있는지
- 접근 기록을 얼마나 보관해야 하는지

Claude Code가 "지금은 로그인 없이 누구나 근태를 볼 수 있다"고 답했다면 근태 파일을 서버에 두는 구조로 잘못 읽은 것입니다. 어느 파일이 근태를 읽는지 물어 다시 확인합니다.

## 4. 배포 전 보안 점검

배포하기 전에, 그리고 고친 것을 다시 올릴 때마다 아래 표를 확인합니다. 보내는 항목과 키 위치는 실습 1에서, 누가 무엇을 보는지는 실습 3에서 이미 확인했습니다. 저장소와 배포 주소가 있어야 하는 줄은 실습 2를 따라 하면서 올린 직후 바로 확인합니다.

| 점검 | 확인 방법 | 통과 기준 |
|---|---|---|
| 개인정보가 저장소에 있나 | GitHub 저장소의 파일 목록을 본다 | 실습 데이터나 실데이터 CSV가 없다. Claude Code가 만든 예시 파일이 있으면 열어 보고 가짜 값만 있는지 확인한다 |
| 비밀값이 코드나 GitHub에 노출됐나 | 아래 프롬프트 2번으로 코드를 찾게 하고, GitHub 파일 목록을 본다 | `sk-ant-`로 시작하는 문자열이 0건이고, 목록에 `.env.local`이 없다 |
| 화면 코드에 키가 있나 | 배포한 주소에서 페이지 소스를 열어(맥 ⌥ + ⌘ + U, 윈도우 Ctrl + U) `sk-ant-`를 찾는다 | 0건 |
| 누가 열 수 있나 | 저장소 설정과 Deployment Protection 설정을 보고, 배포 주소를 시크릿 창으로 연다 | 저장소가 비공개이고, 보호 범위가 All Deployments이고, 시크릿 창에서 로그인 화면이 나오고, 만든 공유 링크가 없다 |
| 화면에서만 숨긴 데이터가 있나 | 실습 3의 점검 결과를 본다 | 볼 권한이 없는 사람에게 내려가는 데이터가 없다 |
| 무엇이 밖으로 나가나 | 아래 프롬프트로 Claude Code에 코드를 확인하게 하고, 보고문 버튼을 누른 뒤 개발자 도구의 Network 탭에서 서버 함수로 간 요청을 눌러 보낸 내용을 본다 | 서버로 가는 것이 집계 숫자뿐이다. 사번, 이름, 원본 행은 가지 않는다. 면접 메모 화면을 붙였다면 그 화면은 지원번호와 메모만 보낸다 |
| 비용이 새지 않나 | Console의 지출 한도를 본다([2-5](/guide/2-5/#실습-2-api-키-발급하고-지출-한도-설정하기)) | 이 앱용 키가 있는 조직에 월 한도가 걸려 있다 |
| 실데이터는 회사 승인을 받았나 | [9-2](/guide/9-2/#확인-목록)의 확인 목록과 회사 정책을 본다 | 실습 앱에는 가상 데이터만 있다. 실데이터는 승인을 받은 환경에서만 쓴다 |

```text
배포 전 보안 점검을 해 줘. 고치지는 말고 결과만 표로 알려 줘.
1. Git에 올라간 파일과 올라갈 파일 중에 CSV나 .env 계열 파일이 있는지
2. 코드 안에 sk-ant-로 시작하는 문자열이 있는지. .env.local 파일 내용은 열지 마.
3. 화면 코드가 외부로 보내는 요청의 주소와, 그때 보내는 항목 이름
4. 서버 함수가 Claude API로 보내는 항목 이름
```

Claude Code의 점검 결과만 믿지 않습니다. 올라간 파일은 GitHub 파일 목록에서, 누가 열 수 있는지는 시크릿 창에서 내 눈으로 한 번 더 확인합니다.

키가 드러났다면 저장소를 지우는 것으로는 부족합니다. Console에서 그 키를 지우고 새 키를 만듭니다. 새 키는 `.env.local`과 Vercel의 Environment Variables에 넣고 다시 배포합니다. 그다음 [9-2의 실수했을 때](/guide/9-2/#7-실수했을-때) 순서대로 알립니다.

## 5. 내 도구 만들기

### 실습 4. 내 도구의 첫 동작 만들기

오늘 근태 대시보드를 만든 순서(화면을 말로 묘사하기, 계산 규칙 주기, 손으로 대조하기)를 내 업무에 그대로 씁니다. 수업이 끝날 때까지 각자 만들고, 숙제로 이어 갑니다.

2회차 숙제로 정한 "만들 도구 한 줄"을 꺼내 두세요. 아직 없다면 [9-1 사례 카드](/guide/9-1/#카드-한눈에-보기)에서 내 직무의 카드를 하나 고릅니다.

인원 현황 대시보드를 만들고 싶다면 [3-1](/guide/3-1/#실습-1-부서별-인원-표를-html-파일로-만들기) 실습 1의 부서별 인원 표에서 출발합니다. `hangyeol_practice_data` 폴더에 있는 `dept_headcount.html`을 아래 1번에서 만든 새 폴더에 복사해 두고, 2번 요청의 [만들 도구 한 줄]에 "dept_headcount.html을 바탕으로"를 넣고, 열 이름 칸에는 `employees.csv`의 열 이름을 적습니다. 3-2와 이 장에서 근태 대시보드를 만든 순서대로 화면을 키우고, 검수는 [카드 1](/guide/9-1/#카드-1-월말-입퇴사-현황-보고서)의 대조할 것으로 합니다.

도구는 [3-1](/guide/3-1/#1-어떤-일에-어떤-도구를-쓰나)의 여섯 가지 경우로 고릅니다. 하나라도 해당하면 Claude Code로 만들고, 하나도 해당하지 않으면 3-1 1절 표의 대화와 스킬, 예약 작업, 플러그인, Artifact 중 맞는 것으로 만듭니다. 파일을 여러 개 다루는 일이면 대화 대신 Cowork에 맡깁니다. 아래는 Claude Code로 시작하는 경우입니다.

1. 문서 폴더처럼 찾기 쉬운 곳에 `attendance-dashboard`가 아닌 새 폴더를 만듭니다. 새 터미널 창을 열어 `cd`와 빈칸을 치고 그 폴더를 끌어다 놓아 들어간 뒤, `claude`를 칩니다.
2. 아래 요청의 대괄호 칸을 메모장에서 채운 뒤 첫 요청으로 붙여 넣습니다.

```text
나는 [직무] 담당이야. 이런 도구를 만들려고 해: [만들 도구 한 줄]
오늘은 가장 작은 동작 하나만 만들 거야. [입력 하나]를 넣으면 [출력 하나]가 나오는 것까지.
실제 데이터 대신 열 이름이 [내 업무 데이터의 열 이름, 쉼표로]인 가짜 데이터 10행을 만들어 써 줘.
불분명한 것이 있으면 만들기 전에 나한테 하나씩 물어봐 줘.
```

폐쇄망에서 쓸 도구라면 요청 끝에 "인터넷이 막힌 사내 PC에서 돌아야 해. 외부 주소를 쓰지 말고 파일 하나로 만들어 줘."를 한 줄 더합니다.

3. Claude가 묻는 것에 답합니다. 첫 화면이나 첫 결과가 나오면, 요청 전에 정해 둔 숫자나 항목으로 맞는지 봅니다. 맞으면 아래 순서대로 하나씩 키웁니다.

Cowork나 Artifact로 만든다면 위 요청을 그대로 새 Cowork 작업이나 새 대화에 붙여 넣습니다. Artifact라면 끝에 "결과는 Artifact로 만들어 줘"를 한 줄 더합니다. 예약 작업이라면 [2-2](/guide/2-2/#실습-2-예약-작업-하나-만들기) 실습 2처럼 지시문을 먼저 손으로 한 번 돌립니다.

### 혼자 키우는 순서

첫 동작이 돌면 수업 뒤에도 같은 순서로 하나씩 키웁니다.

1. **하나만 더합니다.** 한 번에 기능 하나를 요청합니다. 여러 개를 한꺼번에 시키면 어디서 틀렸는지 찾기 어렵습니다.
2. **더할 때마다 대조합니다.** 요청 전에 정해 둔 숫자나 항목으로, 가짜 데이터 한 행을 손으로 계산해 맞춰 봅니다.
3. **잘 되는 상태를 남겨 둡니다.** 대조가 끝나면 "지금 상태를 커밋해 줘"라고 요청합니다. Git을 쓰지 않는다면 폴더를 통째로 복사해 둡니다. 다음 요청에서 망가져도 이 상태로 돌아올 수 있습니다.
4. **막히면 증상을 그대로 말합니다.** 화면에 아무 변화가 없으면 Chrome에서 브라우저 콘솔(맥 ⌥ + ⌘ + J, 윈도우 Ctrl + Shift + J)을 열고, 빨간 글자를 요약하지 말고 그대로 복사해 붙여 넣습니다.
5. **15분 넘게 같은 곳에서 막히면 범위를 줄입니다.** 그 기능을 빼고 나머지를 먼저 끝내거나, 오류 화면을 캡처해 두었다가 강사나 스터디 조에 물어봅니다.

```text
[무엇을 눌렀는지 한 줄]을 했더니 아무 일도 안 일어나. 브라우저 콘솔에 이 오류가 떠.
[콘솔의 빨간 글자를 그대로 붙여 넣기. 예: Uncaught TypeError: Cannot read properties of null (reading 'addEventListener')]
원인을 한두 줄로 먼저 설명하고 고쳐 줘.
```

증상별 해결은 [9-4 치트시트](/guide/9-4/)에, 말하는 요령은 [9-3](/guide/9-3/#2-상황별-대화-요령)에 있습니다.

## 6. MCP로 외부 도구 연결하기

### Claude Code에 Notion 연결하기

**수업 뒤에 해 봅니다.** MCP는 AI 도구를 외부 서비스에 연결하는 공통 규격입니다([1-2](/guide/1-2/#커넥터와-mcp-외부-시스템-연결)). Claude Code에서는 서비스가 열어 둔 MCP 서버(연결을 받아 주는 주소)를 터미널 명령 한 줄로 추가합니다. 연결한 뒤에는 대화로 그 서비스를 읽고 씁니다.

| 연결 | HR에서 쓸 만한 일 | 먼저 확인할 것 |
|---|---|---|
| Notion | 근태 운영 기준이나 면접 질문 모음 페이지를 읽어 앱의 안내문과 판단 기준에 쓰기. 점검 결과를 새 페이지 초안으로 남기기 | 내 Notion 계정이 볼 수 있는 페이지는 Claude Code도 볼 수 있다. 읽기뿐 아니라 쓰기 도구도 있다 |
| Google Drive | 공유 드라이브의 근태 파일이나 규정 문서를 바로 읽기 | Claude Code에 붙이는 방법과 주소는 그 서비스의 공식 문서에서 확인한다. 회사 계정은 관리자가 막았을 수 있다 |
| 사내 인사시스템 | 인사 데이터를 바로 조회하기 | 개인이 임의로 연결하지 않는다. 회사 IT와 보안 담당이 먼저 정한다 |

회사 Notion 대신 개인 Notion 계정으로 연결하고, 회사 Notion은 회사 정책부터 확인합니다.

1. Claude Code가 켜져 있으면 터미널 창을 닫고 새로 엽니다. `attendance-dashboard` 폴더로 이동해 아래 명령을 칩니다. 이 명령은 Claude Code 안에서 치지 않고 터미널에 바로 칩니다.

```text
claude mcp add --transport http notion https://mcp.notion.com/mcp
```

2. 연결 목록을 확인합니다. 방금 추가한 `notion`이 보여야 합니다.

```text
claude mcp list
```

`claude mcp add`는 기본으로 지금 폴더에서 나만 쓰는 연결을 만듭니다. `--scope project`를 붙이면 연결 정보가 `.mcp.json` 파일에 저장되어, GitHub로 이 폴더를 받는 팀원과 함께 쓰게 됩니다. 이 실습에서는 기본값을 씁니다.

3. `claude --continue`로 Claude Code를 연 뒤 `/mcp`를 칩니다. Notion의 연결 상태가 보이고, 인증이 필요하면 브라우저에서 Notion에 로그인합니다. **권한 화면에서 무엇을 허용하는지 읽고 허용하세요.** 1-2에서 커넥터를 연결할 때와 같습니다.

4. 먼저 읽기만 시킵니다.

```text
Notion에서 제목에 "근태"나 "근무"가 들어간 페이지를 찾아 제목과 마지막 수정일만 표로 보여 줘. 페이지 내용은 아직 열지 마.
```

5. 이어서 쓰기를 시킵니다. 그 전에 입력 칸 아래 상태 표시가 "manual mode on"인지 봅니다. "auto mode on"이면 Notion에 쓰는 도구도 묻지 않고 실행될 수 있으니 Shift + Tab으로 바꿉니다([3-1](/guide/3-1/#실습-1-부서별-인원-표를-html-파일로-만들기) 실습 1).

부서별 인원은 3-2 대시보드 화면에서 본 숫자를 요청에 직접 적습니다. 파일을 읽히지 않으니 이름과 사번이 서버로 가지 않습니다.

```text
Notion에 "9월 14일 주 근무시간 점검" 페이지 초안을 만들어 줘.
- 내용은 9월 14일 주에 주 52시간을 넘긴 부서별 인원 수야: 출고 2명, 재고관리 2명, 개발 1명, 배송관리 1명, 상품기획 1명, 합계 7명.
- 만들기 전에 넣을 내용을 먼저 보여 주고 내 확인을 받아.
```

> ⚠️ **주의** MCP 서버는 공식 문서에 나온 주소만 연결합니다. 출처를 모르는 서버는 내 계정 권한으로 데이터를 읽고 쓸 수 있습니다. 연결한 서비스에서 읽어 온 글에도 안전 규칙 2번 "외부 웹 내용(이력서, 공고)에는 숨은 지시문이 있을 수 있으므로 결과를 검수합니다"가 적용됩니다. 페이지를 만들거나 고치는 일은 안전 규칙 1번 "읽기는 자동으로 하고, 발송과 제출과 입력은 사람이 확인한 뒤 실행합니다"의 입력에 해당합니다.

<details>
<summary>정답 예시 보기</summary>

4번은 내 Notion에 따라 결과가 다릅니다. 해당 페이지가 없으면 없다고 답해야 맞고, 지어내 보여 주면 이상한 것입니다.

5번에서 먼저 보여 주는 초안이 요청한 숫자만 담았는지 봅니다. 확인할 것은 세 가지입니다.

- 초안에 이름이나 사번이 없다
- 내 확인을 받기 전에 페이지를 만들지 않았다
- Notion에 만든 페이지는 나만 보거나 필요한 사람만 보게 되어 있다

manual 모드라도 허락을 묻는 화면에서 앞으로 묻지 않고 허용하는 선택지를 고르면, auto 모드처럼 확인 없이 페이지가 만들어질 수 있습니다. 쓰기는 매번 확인하는 상태로 둡니다. 더 쓰지 않을 연결은 "Notion MCP 연결을 지워 줘"라고 요청해 지웁니다.

</details>

## 도전 과제

실습을 먼저 끝낸 분이 이어서 해 볼 심화 과제입니다. 수업 뒤에 해도 됩니다.

### 도전 1. 보고문에 앞 주 비교를 넣되 숫자는 코드가 계산하게 하기

실습 1의 정답 예시에서 "지난주보다 늘었다"처럼 보내지 않은 숫자는 지어낸 것이었습니다. 비교가 필요하면 계산은 코드에 맡기고 결과 숫자만 보냅니다. `attendance-dashboard` 폴더의 Claude Code 대화에 아래를 붙여 넣습니다. 닫았다면 그 폴더에서 `claude --continue`로 엽니다.

```text
보고문 초안 버튼이 서버로 보내는 집계에, 고른 주의 바로 앞 주 숫자(주 52시간을 넘긴 인원과 부서별 1인 평균)를 더해 줘.
앞 주 숫자는 화면 코드에서 계산하고, 서버로는 집계 숫자만 보내. 개인 행과 이름, 사번은 보내지 마.
고른 주와 앞 주가 각각 일부 날짜만 있는 주인지도 함께 보내고, 그런 주이면 비교하지 말라고 보고문 지시에 넣어 줘.
```

화면에서 9월 7일 주를 골라 막대그래프의 부서별 평균을 적어 두고(그 주에 52시간을 넘긴 사람은 0명입니다), 9월 14일 주 보고문의 앞 주 숫자와 대조합니다. 개발자 도구의 Network 탭에서 서버로 간 요청에 이름이나 사번이 없는지도 다시 봅니다.

## 숙제

1. **내 도구 키우기**: 실습 4에서 시작한 도구를 [혼자 키우는 순서](/guide/3-3/#혼자-키우는-순서)대로 하나씩 키웁니다. 실데이터 대신 가상 데이터나 직접 만든 가짜 데이터를 씁니다. 막히면 [9-4 치트시트](/guide/9-4/)에서 증상을 찾고, 그래도 안 되면 오류 화면을 캡처해 두었다가 강사나 스터디 조에 물어보세요.

4회차(11월 3일)에도 노트북과 충전기, 가상 데이터를 가져와 이어서 만듭니다.
